## 1. PL/SQL이란?

**PL/SQL** = **P**rocedural **L**anguage / **SQL**. Oracle이 SQL을 확장한 절차형 언어.

타 DBMS의 절차형 언어:
- **PL/SQL**: Oracle
- **T-SQL**: SQL Server
- **PL/pgSQL**: PostgreSQL

## 2. 블록 구조 ⭐⭐⭐ (시험 빈출)

```sql
DECLARE          -- (선택) 변수, 커서, 예외 선언
   v_count NUMBER := 0;
BEGIN            -- (필수) 실행부
   SELECT COUNT(*) INTO v_count FROM emp;
   DBMS_OUTPUT.PUT_LINE('Count: ' || v_count);
EXCEPTION        -- (선택) 예외 처리부
   WHEN NO_DATA_FOUND THEN
      DBMS_OUTPUT.PUT_LINE('데이터 없음');
   WHEN OTHERS THEN
      DBMS_OUTPUT.PUT_LINE('Error: ' || SQLERRM);
END;             -- (필수) 블록 종료
/
```

> 🔑 **암기법: "데비익엔"** (DECLARE → BEGIN → EXCEPTION → END)

| 부분 | 필수? | 역할 |
|---|---|---|
| DECLARE | 선택 | 변수·커서·예외 선언 |
| **BEGIN** | **필수** | 실행 로직 |
| EXCEPTION | 선택 | 예외 처리 |
| **END** | **필수** | 블록 종료 |

## 3. 블록 종류

| 종류 | 설명 |
|---|---|
| **익명 블록** | 일회성 실행, 저장 안 됨 |
| **저장 프로시저** | `CREATE PROCEDURE`, 재사용 |
| **저장 함수** | `CREATE FUNCTION`, 값 반환 |
| **트리거** | 이벤트 기반 자동 실행 |
| **패키지** | 관련 프로시저·함수 묶음 |

## 4. 변수 ⭐

```sql
DECLARE
   v_id NUMBER := 100;                  -- 명시적 타입
   v_name VARCHAR2(50);
   v_emp emp%ROWTYPE;                   -- 테이블 행과 동일 구조
   v_sal emp.sal%TYPE;                  -- 특정 컬럼 타입
   v_today DATE DEFAULT SYSDATE;
BEGIN
   ...
END;
```

> 🔑 **`%ROWTYPE`, `%TYPE`**: 컬럼 타입 변경 시 자동 반영 → 유지보수 ↑

## 5. 조건문

```sql
-- IF / ELSIF / ELSE
IF v_sal >= 3000 THEN
   v_grade := 'A';
ELSIF v_sal >= 2000 THEN
   v_grade := 'B';
ELSE
   v_grade := 'C';
END IF;

-- CASE
v_grade := CASE
   WHEN v_sal >= 3000 THEN 'A'
   WHEN v_sal >= 2000 THEN 'B'
   ELSE 'C'
END;
```

## 6. 반복문

### LOOP / EXIT

```sql
LOOP
   v_count := v_count + 1;
   EXIT WHEN v_count >= 10;
END LOOP;
```

### WHILE

```sql
WHILE v_count < 10 LOOP
   v_count := v_count + 1;
END LOOP;
```

### FOR

```sql
FOR i IN 1..10 LOOP
   DBMS_OUTPUT.PUT_LINE(i);
END LOOP;

-- 역순
FOR i IN REVERSE 1..10 LOOP ... END LOOP;
```

### 커서 FOR LOOP

```sql
FOR rec IN (SELECT empno, ename FROM emp WHERE deptno = 10) LOOP
   DBMS_OUTPUT.PUT_LINE(rec.empno || ': ' || rec.ename);
END LOOP;
```

## 7. 예외 처리 ⭐⭐

```sql
BEGIN
   SELECT sal INTO v_sal FROM emp WHERE empno = 99999;
EXCEPTION
   WHEN NO_DATA_FOUND THEN
      DBMS_OUTPUT.PUT_LINE('사원 없음');
   WHEN TOO_MANY_ROWS THEN
      DBMS_OUTPUT.PUT_LINE('여러 건 조회됨');
   WHEN OTHERS THEN
      DBMS_OUTPUT.PUT_LINE('SQLCODE: ' || SQLCODE);
      DBMS_OUTPUT.PUT_LINE('SQLERRM: ' || SQLERRM);
END;
```

### 사전 정의 예외

| 예외 | 발생 시점 |
|---|---|
| `NO_DATA_FOUND` | SELECT INTO 결과 없음 |
| `TOO_MANY_ROWS` | SELECT INTO 다중 행 |
| `DUP_VAL_ON_INDEX` | UNIQUE 중복 |
| `ZERO_DIVIDE` | 0 나눗셈 |
| `OTHERS` | 모든 예외 catch |

> 🔑 **암기법**: "Not Found·Too Many·Dup·Zero·Others"

## 8. 프로시저 vs 함수 ⭐⭐

### PROCEDURE — 값 반환 안 함

```sql
CREATE OR REPLACE PROCEDURE raise_sal(
   p_empno IN NUMBER,
   p_amount IN NUMBER
)
IS
BEGIN
   UPDATE emp SET sal = sal + p_amount WHERE empno = p_empno;
   COMMIT;
END;
/

-- 호출
EXEC raise_sal(7369, 100);
```

### FUNCTION — 값 반환

```sql
CREATE OR REPLACE FUNCTION get_annual_sal(
   p_empno IN NUMBER
) RETURN NUMBER
IS
   v_sal NUMBER;
BEGIN
   SELECT sal INTO v_sal FROM emp WHERE empno = p_empno;
   RETURN v_sal * 12;
END;
/

-- 호출 (SQL에서도 가능)
SELECT get_annual_sal(7369) FROM dual;
```

### 차이 비교 ⭐

| | PROCEDURE | FUNCTION |
|---|---|---|
| 값 반환 | ✗ | **○ (RETURN 필수)** |
| SQL에서 호출 | ✗ | ○ (SELECT 등) |
| 호출 방법 | EXEC, CALL | 표현식 안에서 |
| OUT 파라미터 | ○ | △ (지양) |

### 파라미터 모드

| 모드 | 방향 |
|---|---|
| **IN** (기본) | 호출자 → 프로시저 |
| **OUT** | 프로시저 → 호출자 |
| **IN OUT** | 양방향 |

## 9. 트리거 (Trigger) ⭐⭐

```sql
CREATE OR REPLACE TRIGGER trg_emp_log
AFTER INSERT OR UPDATE OR DELETE ON emp
FOR EACH ROW
BEGIN
   IF INSERTING THEN
      INSERT INTO emp_log VALUES (:NEW.empno, 'INSERT', SYSDATE);
   ELSIF UPDATING THEN
      INSERT INTO emp_log VALUES (:NEW.empno, 'UPDATE', SYSDATE);
   ELSIF DELETING THEN
      INSERT INTO emp_log VALUES (:OLD.empno, 'DELETE', SYSDATE);
   END IF;
END;
```

> 🔑 **`:NEW`, `:OLD`**: 변경 후 / 변경 전 행

### 트리거 종류

| 시점 | 단위 | 설명 |
|---|---|---|
| **BEFORE** | STATEMENT | 문장 실행 전, 1번 |
| BEFORE | FOR EACH ROW | 각 행 처리 전 |
| **AFTER** | STATEMENT | 문장 실행 후, 1번 |
| AFTER | FOR EACH ROW | 각 행 처리 후 |
| **INSTEAD OF** | (뷰) | DML 대신 실행 |

> 🔑 **암기법: "BAI × SR"** (Before·After·Instead Of × Statement·Row)

## 10. ⚠️ 자주 틀리는 함정

1. **\"DECLARE는 필수\"** → ✗ 선택
2. **\"FUNCTION은 SQL 안에서 호출 불가\"** → ✗ 가능
3. **\"PROCEDURE도 RETURN 필수\"** → ✗ 함수만
4. **\":NEW.col은 OLD 값\"** → ✗ NEW는 변경 후
5. **\"FOR EACH ROW 없으면 행마다 실행\"** → ✗ 문장 단위
6. **\"WHEN OTHERS는 모든 에러 catch\"** → ○
7. **\"%TYPE은 변수 선언만\"** → ✗ 파라미터에도 사용

## 11. 📝 기출 출제 패턴

### 패턴 A: 블록 구조 순서 ⭐
> \"PL/SQL 블록 구조를 올바르게 나열하면?\"
- DECLARE → BEGIN → EXCEPTION → END

### 패턴 B: 트리거 종류
> \"트리거의 종류가 아닌 것은?\"
- BEFORE, AFTER, INSTEAD OF만 (WHENEVER 같은 가짜 답)

### 패턴 C: 프로시저 vs 함수
> \"FUNCTION의 특징은?\"
- RETURN 필수, SQL 안에서 호출 가능

### 패턴 D: 예외 처리
> \"OTHERS의 역할은?\"
- 모든 예외 catch

## 12. 📌 실전 치트시트

> **핵심 구문 + 함정 + 빈출 패턴**

✅ **블록 구조 = 데비익엔**:
   ```
   DECLARE  → BEGIN  → EXCEPTION  → END
   (선택)     (필수)    (선택)        (필수)
   ```

✅ **변수 타입 참조**:
   - `%TYPE`: 컬럼 타입 가져옴
   - `%ROWTYPE`: 행 전체 구조

✅ **예외 처리**:
   - `NO_DATA_FOUND`: SELECT INTO 0행
   - `TOO_MANY_ROWS`: SELECT INTO 다중행
   - `OTHERS`: 모든 예외

✅ **PROCEDURE vs FUNCTION**:
   - PROCEDURE: 값 반환 ✗, EXEC
   - FUNCTION: **RETURN 필수**, SQL에서 호출 가능

✅ **파라미터 모드**: IN(기본) · OUT · IN OUT

✅ **트리거 종류**:
   - BEFORE / AFTER / INSTEAD OF
   - STATEMENT / FOR EACH ROW
   - `:NEW` = 새 값, `:OLD` = 이전 값

✅ **빈출**: \"트리거의 6종 조합\"

✅ **빈출**: \"%ROWTYPE은 테이블 행 구조 가져옴\"

| 항목 | 암기법 |

| 블록 구조 | **데비익엔** (DECLARE·BEGIN·EXCEPTION·END) |
| 변수 참조 | **%TYPE = 컬럼 타입, %ROWTYPE = 행 타입** |
| 예외 종류 | **No Data·Too Many·Dup·Zero·Others** |
