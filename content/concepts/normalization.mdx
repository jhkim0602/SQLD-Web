## 정규화의 목적

데이터 **중복을 제거**하고 **이상 현상(Anomaly)**을 방지하여 데이터 무결성을 보장한다.

### 이상 현상(Anomaly) 3가지
- **삽입 이상**: 원치 않는 데이터까지 함께 삽입해야 하는 문제
- **갱신 이상**: 일부만 갱신되어 데이터 불일치
- **삭제 이상**: 삭제 시 필요한 정보까지 함께 사라짐

## 정규형 단계

### 1NF (제1정규형)

> 모든 속성이 **원자값(Atomic)**을 가져야 한다.

위반 예: 한 칸에 콤마로 여러 값 저장.

### 2NF (제2정규형)

> 1NF + **부분함수 종속 제거**

복합키의 **일부에만 종속**되는 속성이 있으면 위반. 단일키이면 자동 만족.

### 3NF (제3정규형)

> 2NF + **이행적 종속(Transitive) 제거**

A → B → C 처럼 PK가 아닌 속성을 거쳐 종속되면 위반.

```
주문(주문번호, 고객번호, 고객명)
   주문번호 → 고객번호 → 고객명  ← 이행 종속
```

### BCNF (Boyce-Codd)

> 3NF + 모든 **결정자(Determinant)가 후보키**

3NF인데도 결정자가 후보키가 아닌 경우가 BCNF 위반.

## 반정규화 (Denormalization)

> 정규화가 항상 옳지는 않다.

성능, 단순성, 빈번한 조인 회피를 위해 의도적으로 중복을 허용하는 것. 다만 데이터 정합성 관리 부담이 늘어남.

## 함정 체크리스트

- 부분 종속 → **2NF** 위반
- 이행 종속 → **3NF** 위반
- 결정자가 후보키 아님 → **BCNF** 위반
