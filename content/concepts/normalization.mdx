## 정규화의 목적

> **데이터 중복을 제거**하고 **이상 현상**을 방지해 데이터 무결성을 보장.

## 이상 현상 (Anomaly)

비정규화 테이블에서 발생하는 3가지 문제.

### 예시 비정규화 테이블

| 학번 | 과목 | 점수 | 학과 | 학과장 |
|---|---|---|---|---|
| 1 | DB | 90 | 컴공 | 김교수 |
| 1 | 알고 | 85 | 컴공 | 김교수 |
| 2 | DB | 80 | 전자 | 이교수 |

**문제점**:
- 김교수가 컴공 학과장이라는 정보가 여러 행에 중복
- 학번 1번 학생이 휴학(삭제)되면 컴공 학과장 정보도 사라질 위험

### 3대 이상 현상

| 이상 | 설명 | 위 예 |
|---|---|---|
| **삽입 이상** | 원치 않는 정보까지 함께 삽입 | 학생 없이 학과/학과장 정보 등록 불가 |
| **갱신 이상** | 일부만 갱신되어 불일치 | 학과장 변경 시 모든 행 갱신 필요 |
| **삭제 이상** | 필요한 정보까지 함께 사라짐 | 마지막 학생 삭제 시 학과 정보 소실 |

## 함수 종속성 (Functional Dependency)

`X → Y`: X 값이 결정되면 Y 값이 유일하게 결정됨.

### 종속의 종류

| 종속 | 정의 | 정규화 |
|---|---|---|
| **완전 함수 종속** | 복합키 전체에 종속 | OK |
| **부분 함수 종속** | 복합키의 **일부**에만 종속 | **2NF 위반** |
| **이행 함수 종속** | A → B → C (A → C가 B를 거침) | **3NF 위반** |

## 정규형 단계

### 1NF (제1정규형)

> 모든 속성이 **원자값(Atomic)**을 가져야 한다.

위반 예:
- 한 컬럼에 콤마로 여러 값 (`'서울, 부산'`)
- 반복 그룹 컬럼 (`전화1, 전화2, 전화3`)
- 배열·JSON 형태

```sql
-- ✗ 1NF 위반
CREATE TABLE 학생 (
  학번 INT,
  취미 VARCHAR(100)   -- '게임, 영화, 독서'
);

-- ✓ 1NF 만족
CREATE TABLE 학생 (학번 INT PRIMARY KEY);
CREATE TABLE 학생_취미 (
  학번 INT,
  취미 VARCHAR(50),
  PRIMARY KEY (학번, 취미)
);
```

### 2NF (제2정규형)

> 1NF + **부분 함수 종속 제거**

복합키(예: `(주문번호, 상품번호)`)의 일부에만 종속되는 속성이 있으면 위반. **단일키일 때는 자동 만족**.

위반 예:
```
주문상세(주문번호, 상품번호, 수량, 상품명, 단가)
PK: (주문번호, 상품번호)
- 수량은 (주문번호, 상품번호)에 종속 → OK
- 상품명, 단가는 상품번호에만 종속 → 부분 종속 → 2NF 위반
```

해결:
```
주문상세(주문번호, 상품번호, 수량)
상품(상품번호, 상품명, 단가)
```

### 3NF (제3정규형)

> 2NF + **이행 함수 종속 제거**

`A → B → C` 형태로 PK가 아닌 속성을 거쳐 종속되면 위반.

위반 예:
```
사원(사번, 이름, 부서번호, 부서명)
- 사번 → 부서번호 → 부서명 (이행 종속)
```

해결:
```
사원(사번, 이름, 부서번호 FK)
부서(부서번호, 부서명)
```

### BCNF (Boyce-Codd Normal Form)

> 3NF + 모든 **결정자(Determinant)가 후보키**

3NF는 만족하지만 BCNF는 위반하는 사례가 있다.

위반 예:
```
수강(학생, 과목, 강사)
PK: (학생, 과목)
함수 종속:
  (학생, 과목) → 강사  ← PK 종속, OK
  강사 → 과목          ← 강사가 결정자이지만 후보키 아님 → BCNF 위반
```

해결:
```
수강(학생, 강사)
강사_과목(강사, 과목)
```

### 4NF, 5NF (참고)

- **4NF**: 다중값 종속(MVD) 제거
- **5NF**: 조인 종속(JD) 제거

실무·시험에서는 BCNF까지만 깊이 다룸.

## 정규화 판별 체크리스트

| 체크 | 위반 시 |
|---|---|
| 한 칸에 여러 값? | 1NF 위반 |
| 복합키 일부에만 종속? | 2NF 위반 |
| PK가 아닌 속성을 거쳐 종속? | 3NF 위반 |
| 결정자가 후보키가 아님? | BCNF 위반 |

## 반정규화 (Denormalization)

> 정규화가 항상 옳지는 않다.

성능을 위해 의도적으로 중복 허용.

### 반정규화 기법

| 기법 | 설명 |
|---|---|
| **테이블 병합** | 자주 조인되는 테이블을 합침 |
| **테이블 분할** | 자주 사용 vs 가끔 사용 컬럼 분리 (수직), 또는 행 분할 (수평) |
| **중복 컬럼 추가** | 조인 회피용 |
| **파생 컬럼 저장** | 계산 결과 미리 저장 |
| **요약 테이블** | 집계 결과 별도 테이블 |
| **이력 테이블** | 변경 이력 분리 |

### 반정규화 시 고려사항

- 데이터 **정합성 관리 부담** 증가
- 갱신이 빈번하면 오히려 성능 ↓
- **정규화 후 측정**한 뒤 적용

## 시험 빈출 포인트

> 📌 **꼭 외울 것**
>
> 1. **3대 이상**: 삽입/갱신/삭제 이상
> 2. **1NF**: 원자값
> 3. **2NF**: 부분 종속 제거 (복합키일 때만 발생)
> 4. **3NF**: 이행 종속 제거
> 5. **BCNF**: 모든 결정자가 후보키
> 6. 단일키면 2NF 자동 만족
> 7. 함수 종속 표기: `X → Y`
> 8. 반정규화는 **성능 vs 정합성** 트레이드오프
> 9. 정규화 단계는 누적: 3NF면 1NF, 2NF도 만족
> 10. 정규화 → 측정 → 필요 시 반정규화 (순서 중요)
