## 1. 정의

**식별자(Identifier)**는 엔터티의 인스턴스를 **유일하게 구분**할 수 있는 속성 또는 속성의 집합이다. RDBMS에서는 **PRIMARY KEY**로 구현.

## 2. 식별자의 4대 특성 ⭐⭐⭐ (가장 빈출)

| # | 특성 | 설명 |
|---|---|---|
| 1 | **유일성 (Uniqueness)** | 모든 인스턴스를 유일하게 식별 |
| 2 | **최소성 (Minimality)** | 유일성을 만족하는 **최소** 속성 수 |
| 3 | **불변성 (Immutability)** | 한 번 부여되면 **변하지 않음** |
| 4 | **존재성 (Existence)** | 반드시 값 존재 — **NULL 불허** |

> 🔑 **암기법: "유최불존"** (유일성·최소성·불변성·존재성)

> ⚠️ \"대표성\"이라고 표현하는 책도 있음. 대표성 = 엔터티 대표 식별자.

## 3. 식별자의 분류 (4가지 기준) ⭐⭐

### 3-1. 대표성에 따른 분류

| 분류 | 설명 |
|---|---|
| **주식별자 (Primary Identifier)** | 엔터티의 대표 식별자, PK |
| **보조식별자 (Alternate Identifier)** | 그 외 유일하게 식별 가능한 속성, AK |

### 3-2. 자생 여부에 따른 분류

| 분류 | 설명 |
|---|---|
| **내부 식별자 (Internal)** | 엔터티 내에서 자생 |
| **외부 식별자 (External)** | 다른 엔터티와의 관계로 발생 (FK 포함) |

### 3-3. 속성 수에 따른 분류

| 분류 | 설명 |
|---|---|
| **단일 식별자** | 1개 속성 (예: 사번) |
| **복합 식별자** | 2개 이상 속성 (예: 주문번호 + 상품번호) |

### 3-4. 대체 여부에 따른 분류 ⭐ 빈출

| 분류 | 설명 | 예시 |
|---|---|---|
| **본질 식별자 (Natural)** | 업무에서 자연 발생 | 주민등록번호, 사업자번호 |
| **인조 식별자 (Surrogate)** | 인위적으로 부여 (의미 X) | 시퀀스 일련번호, UUID |

> 🔑 **암기법: "대자속대"** (대표성·자생·속성수·대체 여부)

## 4. 키의 종류 (Keys) ⭐⭐⭐

| 키 | 정의 | 유일성 | 최소성 | NULL |
|---|---|---|---|---|
| **슈퍼키 (Super Key)** | 유일성만 만족 | ✓ | — | — |
| **후보키 (Candidate Key)** | 유일성 + 최소성 | ✓ | ✓ | 불가 |
| **주키 (Primary Key)** | 후보키 중 대표로 선정 | ✓ | ✓ | **불가** |
| **대체키 (Alternate Key)** | 후보키 중 PK 제외 나머지 | ✓ | ✓ | 가능 |
| **외래키 (Foreign Key)** | 다른 테이블 PK 참조 | — | — | **가능** |

### 키 포함 관계

```
슈퍼키 ⊇ 후보키 ⊇ {주키, 대체키}
```

### 예시

```
학생(학번, 주민번호, 이름, 학과, 학년)

슈퍼키:  {학번, 주민번호}, {학번}, {주민번호}, {학번, 이름}, ...
후보키:  {학번}, {주민번호}                     ← 둘 다 단독으로 유일
주키:    {학번}                                  ← 후보키 중 선정
대체키:  {주민번호}                              ← 후보키 중 PK 외
```

## 5. 본질 vs 인조 식별자 ⭐⭐

| 구분 | 본질 식별자 | 인조 식별자 |
|---|---|---|
| **출처** | 업무에서 자연 발생 | 시스템이 인위적 부여 |
| **의미** | 업무적 의미 있음 | 의미 없음 (순번) |
| **예시** | 주민번호, 사업자번호 | 시퀀스 ID, UUID |
| **장점** | 직관적, 검색 자연스러움 | 변하지 않음, 단순함 |
| **단점** | 변경 가능, 길거나 복잡 | 추가 인덱스 필요 |

### 인조 식별자 도입 시점

1. 본질 식별자가 **자주 변경**됨
2. 본질 식별자가 **너무 김** (성능)
3. 본질 식별자가 **복합키로 너무 복잡**
4. 인조 식별자가 **외부 시스템 연계 용이**

## 6. 주식별자 도출 기준

1. **자주 이용**되는 속성 우선
2. **변경 가능성이 적은** 속성
3. 명칭·이름 같이 **변하기 쉬운 속성 회피**
4. 복합 식별자는 **속성 수를 적게** (보통 7~8개 이하)
5. **너무 긴 속성은 인조 식별자로 대체** 권장

## 7. ⚠️ 자주 틀리는 함정

1. **\"주식별자는 NULL을 가질 수 있다\"** → ✗ **존재성** 위반
2. **\"외래키는 NULL을 가질 수 없다\"** → ✗ **선택 관계라면 허용**
3. **\"후보키는 최소성이 없어도 된다\"** → ✗ 후보키는 최소성 필수
4. **\"슈퍼키 = 주식별자\"** → ✗ 슈퍼키는 최소성 없음
5. **\"인조식별자는 업무 의미가 있다\"** → ✗ **의미 없음**이 핵심
6. **\"주식별자는 한 번 정해지면 변경 가능\"** → ✗ **불변성**
7. **\"본질식별자는 항상 좋다\"** → ✗ 변경·복잡 시 인조 도입

## 8. 📝 기출 출제 패턴

### 패턴 A: 4대 특성
> \"주식별자의 특성으로 적절하지 않은 것은?\"
- 유일·최소·불변·존재 중 하나를 변형
- \"허용성\"이라는 가짜 답에 \"NULL 허용\"이 함정

### 패턴 B: 키의 종류
> \"후보키와 슈퍼키의 차이는?\"
- 최소성 유무가 핵심 구분

### 패턴 C: 본질 vs 인조
> \"인조 식별자에 대한 설명으로 옳지 않은 것은?\"
- 의미 유무, 도입 시점이 함정

### 패턴 D: PK NULL
> \"주식별자는 NULL을 가질 수 있다 (O/X)\"
- 항상 X (존재성)

## 9. 🔑 암기법 종합

| 항목 | 암기법 |
|---|---|
| 4대 특성 | **유최불존** (유일·최소·불변·존재) |
| 4대 분류 기준 | **대자속대** (대표성·자생·속성수·대체) |
| 키 5종 | **슈후주대외** (슈퍼·후보·주·대체·외래) |
| 본질 vs 인조 | **본자(自然)·인조(人造)** |

## 10. 📌 시험 합격 핵심 요약

> **시험장 입실 5분 전 점검**

✅ **주식별자 4대 특성 = 유최불존**
   - **유**일성, **최**소성, **불**변성, **존**재성(NULL 불가)

✅ **키 5종**:
   - 슈퍼키 (유일만)
   - 후보키 (유일+최소)
   - 주키 (후보키 대표)
   - 대체키 (후보키 - 주키)
   - 외래키 (다른 PK 참조, NULL 가능)

✅ **NULL 허용**:
   - PK ✗ / UNIQUE ✓ / FK ✓ (선택 관계)

✅ **본질 vs 인조**:
   - 본질 = 자연 발생, 업무 의미
   - 인조 = 인위, 의미 없음 (시퀀스)

✅ **인조 도입 시점**: 본질이 자주 변경·길거나·복잡할 때

✅ **빈출 함정**: \"주식별자는 NULL 가능\" → 거짓
