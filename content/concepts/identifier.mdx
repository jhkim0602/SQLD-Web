## 1. 식별자란?

**식별자(Identifier)**는 엔터티의 **인스턴스를 유일하게 구분**할 수 있는 속성 또는 속성의 집합이다. RDBMS에서는 **PRIMARY KEY**로 구현된다.

> 💡 식별자 없는 엔터티는 **데이터 무결성을 보장할 수 없다**.

```
[사원]
─────────────
# 사번 (식별자)    ← 인스턴스를 유일하게 구분
  이름
  부서ID
─────────────

7369  홍길동  10
7400  김철수  20
7500  이영희  10
```

## 2. 식별자의 4대 특성 ⭐⭐⭐ (가장 빈출)

| # | 특성 | 영문 | 설명 |
|---|---|---|---|
| 1 | **유일성** | Uniqueness | 모든 인스턴스를 유일하게 식별 |
| 2 | **최소성** | Minimality | 유일성을 만족하는 **최소 속성 수** |
| 3 | **불변성** | Immutability | 한 번 부여되면 **변하지 않음** |
| 4 | **존재성** | Existence | 반드시 값 존재 — **NULL 불허** |

> 🔑 **암기법: \"유최불존\"** (유일성·최소성·불변성·존재성)

### 각 특성 깊이 보기

#### ① 유일성 (Uniqueness)

식별자 값으로 인스턴스를 **단 하나만 식별** 가능해야 함.

```
사원: 7369, 7400, 7500, ...  ← 모두 다름 ✓
```

#### ② 최소성 (Minimality)

유일성을 보장하는 **최소한의 속성**으로 구성. 불필요한 속성을 포함하면 안 됨.

```
{사번}             ← 유일하면서 1개 = 후보키 ✓
{사번, 이름}        ← 유일하지만 이름 없어도 유일 → 슈퍼키 (후보키 X)
```

#### ③ 불변성 (Immutability)

한 번 부여된 식별자 값은 **절대 변경하지 않음**. 변경되면 자식 테이블의 FK까지 모두 갱신해야 함.

```sql
-- ✗ 위험: 사번 변경
UPDATE emp SET empno = 9999 WHERE empno = 7369;
-- → 자식 테이블의 mgr, 자식 테이블의 FK 등 모두 깨질 위험
```

#### ④ 존재성 (Existence)

식별자는 반드시 값이 있어야 함. **NULL 불허**.

```sql
PRIMARY KEY 컬럼에 NULL INSERT → 에러
```

## 3. 식별자의 분류 (4가지 기준) ⭐⭐

### 3-1. 대표성에 따른 분류

| 분류 | 설명 |
|---|---|
| **주식별자 (Primary Identifier)** | 엔터티의 **대표 식별자**, PK |
| **보조식별자 (Alternate Identifier)** | 그 외 유일하게 식별 가능한 속성, AK |

```
사원 엔터티
- 사번 (주식별자) ← PK로 선정
- 주민번호 (보조식별자) ← 유일하지만 PK 외
```

### 3-2. 자생 여부에 따른 분류

| 분류 | 설명 |
|---|---|
| **내부 식별자 (Internal)** | 엔터티 **내에서 자생** |
| **외부 식별자 (External)** | 다른 엔터티와의 **관계로 발생** (FK 포함) |

### 3-3. 속성 수에 따른 분류

| 분류 | 설명 |
|---|---|
| **단일 식별자 (Single)** | **1개 속성** (예: 사번) |
| **복합 식별자 (Composite)** | **2개 이상 속성** (예: 주문번호 + 상품번호) |

### 3-4. 대체 여부에 따른 분류 ⭐ (시험 빈출)

| 분류 | 설명 | 예시 |
|---|---|---|
| **본질 식별자 (Natural)** | 업무에서 **자연 발생** | 주민번호, 사업자번호 |
| **인조 식별자 (Surrogate)** | **인위적으로 부여** (의미 X) | 시퀀스 일련번호, UUID |

> 🔑 **암기법: \"대자속대\"** (대표성·자생·속성수·대체)

## 4. 키의 종류 (Keys) ⭐⭐⭐

| 키 | 정의 | 유일성 | 최소성 | NULL |
|---|---|---|---|---|
| **슈퍼키 (Super Key)** | 유일성만 만족 | ✓ | — | — |
| **후보키 (Candidate Key)** | 유일성 + 최소성 | ✓ | ✓ | 불가 |
| **주키 (Primary Key)** | 후보키 중 대표 | ✓ | ✓ | **불가** |
| **대체키 (Alternate Key)** | 후보키 중 PK 제외 | ✓ | ✓ | 가능 |
| **외래키 (Foreign Key)** | 다른 테이블 PK 참조 | — | — | **가능** |

### 키의 포함 관계

```
슈퍼키 ⊇ 후보키 ⊇ {주키, 대체키}
```

> 🔑 **암기법: \"슈후주대외\"** (슈퍼·후보·주·대체·외래)

### 키 도출 예시

```
학생 엔터티: (학번, 주민번호, 이름, 학과, 학년)

슈퍼키:    {학번}, {주민번호}, {학번, 주민번호}, {학번, 이름}, ... 무수히 많음
후보키:    {학번}, {주민번호}                      ← 단독으로 유일 + 최소
주키 (PK): {학번}                                  ← 대표로 선정
대체키(AK): {주민번호}                              ← PK 외 후보키
외래키 (FK): {학과}                                 ← 학과 엔터티 PK 참조 (있다면)
```

## 5. 본질 vs 인조 식별자 ⭐⭐

### 본질 식별자 (Natural Identifier)

업무에서 자연 발생하는 식별자.

**장점**:
- 직관적 (업무 의미 있음)
- 검색이 자연스러움
- 별도 인덱스 불필요

**단점**:
- 변경 가능성 (예: 주민번호 체계 변경)
- 너무 길거나 복잡할 수 있음
- 외부 노출 시 개인정보 이슈

**예시**: 주민등록번호, 사업자번호, ISBN

### 인조 식별자 (Surrogate Identifier)

시스템이 인위적으로 부여하는 의미 없는 식별자.

**장점**:
- **변하지 않음** (시스템이 부여)
- 단순함 (보통 단일 NUMBER)
- 외부 노출 안전 (의미 없음)
- 성능 좋음 (인덱스 효율)

**단점**:
- 업무 의미 없음 (검색 시 다른 키 필요)
- 인덱스 추가 필요 (보통 본질 식별자에도)

**예시**: SEQUENCE.NEXTVAL, AUTO_INCREMENT, UUID

### 인조 식별자 도입 시점 ⭐

다음 중 하나에 해당하면 도입 고려:

1. 본질 식별자가 **자주 변경**됨
2. 본질 식별자가 **너무 김** (성능)
3. 복합키로 **너무 복잡**함
4. 외부 시스템 **연계 용이성** 필요
5. 개인정보 등 본질 식별자 **노출 제한**

```sql
-- 예: 주문 엔터티
-- 본질: (주문일자, 주문시간, 고객ID, 순번) - 복합 길어짐
-- 인조: order_id NUMBER (시퀀스)  ← 권장
```

## 6. 주식별자 도출 기준

| # | 기준 | 설명 |
|---|---|---|
| 1 | **자주 이용** | 검색에 자주 쓰이는 속성 |
| 2 | **변경 없음** | 변하기 쉬운 속성 회피 |
| 3 | **명칭 회피** | 이름·제목 같은 변경 가능 속성 X |
| 4 | **적은 속성 수** | 복합키는 보통 7~8개 이하 |
| 5 | **긴 속성 대체** | 너무 길면 인조 식별자 |
| 6 | **NULL 회피** | 일부라도 NULL 가능 속성 X |

## 7. FK와 NULL ⭐⭐

| 키 | NULL 허용 |
|---|---|
| **PRIMARY KEY** | ✗ (개체 무결성) |
| **UNIQUE** | **○** (여러 NULL 공존 가능) |
| **FOREIGN KEY** | **○** (선택 관계) |
| **NOT NULL** | ✗ |

> ⚠️ **시험 1순위 함정**: \"FK는 NULL 불가\" → **거짓**.

```sql
-- FK NULL 허용 예
CREATE TABLE emp (
  empno NUMBER PRIMARY KEY,         -- PK: NULL 불가
  ename VARCHAR2(50) NOT NULL,
  deptno NUMBER,                    -- FK: NULL 가능 (부서 미배정)
  CONSTRAINT fk_dept FOREIGN KEY (deptno) REFERENCES dept (deptno)
);
```

## 8. ⚠️ 자주 틀리는 함정

1. **\"주식별자는 NULL을 가질 수 있다\"** → ✗ 존재성 위반
2. **\"외래키는 NULL을 가질 수 없다\"** → ✗ 허용
3. **\"후보키는 최소성이 없어도 된다\"** → ✗ 후보키도 최소성 필수
4. **\"슈퍼키 = 주식별자\"** → ✗ 슈퍼키는 최소성 없음
5. **\"인조식별자는 업무 의미가 있다\"** → ✗ 의미 없음이 특징
6. **\"주식별자는 한 번 정해지면 변경 가능\"** → ✗ 불변성
7. **\"본질식별자는 항상 좋다\"** → ✗ 변경·복잡 시 인조 도입
8. **\"식별자 분류는 3가지 기준\"** → ✗ 4가지 (대자속대)

## 9. 📝 기출 출제 패턴

### 패턴 A: 4대 특성 ⭐ 최빈출
> \"주식별자의 특성으로 적절하지 않은 것은?\"
- 유일·최소·불변·존재 중 하나가 변형
- \"허용성\"이라는 가짜 답에 \"NULL 허용\" 함정

### 패턴 B: 키의 종류
> \"후보키와 슈퍼키의 차이는?\"
- 최소성 유무가 핵심

### 패턴 C: 본질 vs 인조
> \"인조 식별자에 대한 설명으로 옳지 않은 것은?\"
- 의미 유무, 도입 시점이 함정

### 패턴 D: PK NULL
> \"주식별자는 NULL을 가질 수 있다 (O/X)\"
- 항상 X

### 패턴 E: 식별자 분류 기준
> \"식별자 분류 중 잘못 짝지어진 것은?\"
- 대표성/자생/속성수/대체 외에 가짜 답

## 10. 📌 ERD·모델링 한눈

> **분류 · ERD 표기 · 명명 규칙**

✅ **주식별자 4대 특성 = 유최불존**:
   - **유**일성, **최**소성, **불**변성, **존**재성 (NULL 불가)

✅ **키 5종 = 슈후주대외**:
   - 슈퍼키 (유일만)
   - 후보키 (유일+최소)
   - 주키 (후보키 대표)
   - 대체키 (후보키 - 주키)
   - 외래키 (다른 PK 참조, NULL 가능)

✅ **NULL 허용 표**:
   - PK ✗ / UNIQUE ○ / FK ○ / NOT NULL ✗

✅ **본질 vs 인조**:
   - 본질: 자연 발생, 업무 의미
   - 인조: 인위적, 의미 없음 (시퀀스)

✅ **인조 도입 시점**: 본질이 자주 변경·길거나·복잡할 때

✅ **식별자 분류 4기준 = 대자속대**:
   - 대표성: 주식별자/보조식별자
   - 자생: 내부/외부
   - 속성수: 단일/복합
   - 대체: 본질/인조

✅ **빈출 함정**:
   - \"PK는 NULL 가능\" → 거짓
   - \"FK는 NULL 불가\" → 거짓
   - \"슈퍼키 = 후보키\" → 거짓 (최소성 X)

### 🔑 암기법 정리

| 키 5종 | **슈후주대외** (슈퍼·후보·주·대체·외래) |
