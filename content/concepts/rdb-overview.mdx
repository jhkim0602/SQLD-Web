## 1. 관계형 데이터베이스란?

**관계형 데이터베이스(RDB, Relational Database)**는 데이터를 **2차원 표(테이블)** 형태로 저장하고 관리하는 데이터베이스. 1970년 IBM의 **E.F. Codd 박사**가 제안한 관계형 모델에 기반.

> 💡 \"관계\" = 수학의 집합론 **릴레이션(Relation)**에서 유래. 우리가 흔히 말하는 \"테이블 간 관계\"와는 다른 개념.

### 주요 RDBMS

| DBMS | 특징 |
|---|---|
| **Oracle** | 엔터프라이즈 시장 강자, 풍부한 기능 |
| **MySQL** | 오픈소스, 웹 서비스에 광범위 사용 |
| **PostgreSQL** | 오픈소스, 표준 SQL 충실, 확장성 |
| **SQL Server** | Microsoft, .NET 환경에 최적 |
| **MariaDB** | MySQL 포크, 완전 오픈소스 |
| **DB2** | IBM, 메인프레임 |

## 2. 관계형 모델의 핵심 용어 ⭐⭐⭐

| 관계형 모델 용어 | RDBMS 용어 | 설명 |
|---|---|---|
| **릴레이션 (Relation)** | 테이블 (Table) | 데이터의 집합 |
| **튜플 (Tuple)** | 행 (Row, Record) | 한 건의 데이터 |
| **속성 (Attribute)** | 컬럼 (Column, Field) | 데이터의 항목 |
| **도메인 (Domain)** | 값의 범위 | 컬럼이 가질 수 있는 값 집합 |
| **차수 (Degree)** | 컬럼 수 | 속성의 개수 |
| **카디널리티 (Cardinality)** | 행 수 | 튜플의 개수 |

> 🔑 **암기법: \"릴튜속도차카\"**
> 릴레이션·튜플·속성·도메인·차수(컬럼수)·카디널리티(행수)

```
           ┌─ 차수(Degree) = 3 ─┐
           ▼                  ▼
[릴레이션: emp]
┌─────┬────────┬──────────┐
│사번 │이름    │입사일    │   ← 속성 (Attribute)
├─────┼────────┼──────────┤
│7369 │홍길동  │2020-03-01│ ← 튜플 (Tuple)
│7400 │김철수  │2021-05-15│
│7500 │이영희  │2022-01-10│
└─────┴────────┴──────────┘
   ▲
   └─ 카디널리티(Cardinality) = 3
```

## 3. 관계형 모델의 5대 성질

| # | 성질 | 설명 |
|---|---|---|
| 1 | **유일성** | 모든 튜플은 유일 (중복 X) |
| 2 | **무순서 (행)** | 튜플의 순서 무의미 (집합 개념) |
| 3 | **무순서 (열)** | 속성의 순서 무의미 |
| 4 | **속성명 유일** | 한 릴레이션 내 속성명 중복 X |
| 5 | **원자값** | 모든 값은 원자값 (1NF) |

> 💡 **수학의 집합 = 순서 없는 유일한 원소들의 모임**. RDB의 릴레이션도 동일.

```sql
-- 같은 데이터를 다른 순서로 SELECT하면?
SELECT 이름, 사번 FROM emp;
-- = SELECT 사번, 이름 FROM emp;  ← 결과 의미 동일 (순서 다를 뿐)
```

## 4. 코드(Codd)의 12법칙 (간략)

E.F. Codd가 1985년 제안한 \"진정한 관계형 DBMS\" 12조건.

| # | 법칙 | 요약 |
|---|---|---|
| 1 | **정보 표현** | 모든 정보는 테이블의 값으로 표현 |
| 2 | **보장된 접근** | (테이블명, PK, 컬럼명)으로 모든 데이터 접근 가능 |
| 3 | **NULL의 체계적 처리** | NULL은 모든 데이터 타입에서 일관되게 처리 |
| 4 | **온라인 카탈로그** | 데이터 사전을 SQL로 조회 가능 |
| 5 | **포괄적 데이터 부속어** | DDL/DML/DCL을 모두 지원하는 단일 언어 |
| 6 | **뷰 갱신** | 갱신 가능한 뷰는 갱신 가능 |
| 7 | **집합 처리** | INSERT/UPDATE/DELETE를 집합 단위로 |
| 8 | **물리적 데이터 독립성** | 물리 변경이 응용에 영향 X |
| 9 | **논리적 데이터 독립성** | 논리 변경이 응용에 영향 X |
| 10 | **무결성 독립성** | 무결성 제약은 카탈로그에 저장, 응용 코드에 X |
| 11 | **분산 독립성** | 분산 DB의 위치 투명성 |
| 12 | **비파괴 규칙** | 저수준 언어로 무결성 우회 불가 |

> 💡 시험에선 12개 모두 외울 필요는 없으나, **\"코드의 12법칙\" = E.F. Codd의 제안** 정도는 알아두기.

## 5. 관계형 DB의 강점과 약점

### 강점 ✓

| 강점 | 설명 |
|---|---|
| **정합성** | ACID 트랜잭션으로 데이터 무결성 보장 |
| **표준화된 SQL** | 어떤 RDBMS도 표준 SQL 사용 |
| **복잡한 조인** | 다중 테이블 결합으로 풍부한 분석 |
| **선언적 쿼리** | 무엇을(What) 가져올지만 명시 |
| **성숙한 도구** | 수십 년 누적된 도구·라이브러리 |

### 약점 ✗

| 약점 | 설명 |
|---|---|
| **수평 확장 제약** | 샤딩이 복잡 |
| **비정형 데이터** | JSON, 이미지, 그래프 등 표현 어려움 |
| **스키마 변경 비용** | ALTER TABLE이 무겁고 위험 |
| **객체 매핑 부조화** | OO 언어와 객체-관계 불일치 (Impedance Mismatch) |

## 6. RDB vs NoSQL

| 항목 | RDB | NoSQL |
|---|---|---|
| **저장 형식** | 표 (정형) | Document, Key-Value, Graph, Column-family |
| **스키마** | 고정 (rigid) | 유연 (flexible) |
| **쿼리** | SQL (표준) | 다양 (MongoDB, Cypher 등) |
| **트랜잭션** | ACID 강력 | BASE (일부만 ACID) |
| **확장** | 수직 확장 (Scale-Up) | 수평 확장 (Scale-Out) |
| **사용 예** | 금융, ERP, 회계 | SNS, 빅데이터, IoT |
| **대표 DB** | Oracle, MySQL, PostgreSQL | MongoDB, Redis, Cassandra, Neo4j |

> 💡 \"NoSQL\" = Not Only SQL. SQL을 부정하는 게 아니라 보완하는 의미.

## 7. OLTP vs OLAP ⭐

| 항목 | OLTP | OLAP |
|---|---|---|
| **풀네임** | Online **Transaction** Processing | Online **Analytical** Processing |
| **목적** | 일상 업무 처리 | 분석·의사결정 |
| **데이터** | 최신, 운영 데이터 | 누적 이력, 집계 데이터 |
| **트랜잭션 수** | 다수, 짧음 | 소수, 길음 |
| **쿼리 유형** | INSERT/UPDATE/DELETE 위주 | SELECT 집계 위주 |
| **응답 시간** | 밀리초 | 초~분 |
| **정규화** | 정규화 (3NF) | 반정규화 (스타 스키마) |
| **예시** | 주문 처리, 계좌 이체, ERP | 매출 분석, BI 대시보드 |

## 8. RDBMS 아키텍처 개요

```
┌────────────────────────────────┐
│   사용자 / 응용 프로그램          │
└──────────────┬─────────────────┘
               ▼ SQL
┌──────────────────────────────────┐
│  SQL 처리기 (Parser, Optimizer)   │
│  - 파싱 / 의미 분석                │
│  - 옵티마이저 (실행계획 결정)         │
└──────────────┬───────────────────┘
               ▼
┌──────────────────────────────────┐
│  실행 엔진 (Execution Engine)      │
│  - 트랜잭션 관리 (ACID)             │
│  - 동시성 제어 (Lock, MVCC)         │
│  - 복구 (REDO, UNDO)               │
└──────────────┬───────────────────┘
               ▼
┌──────────────────────────────────┐
│  저장소 관리 (Storage Manager)     │
│  - 인덱스, 버퍼, 파일 시스템         │
└──────────────────────────────────┘
```

## 9. ⚠️ 자주 틀리는 함정

1. **\"릴레이션 = 관계\"** → △ 릴레이션(Relation)은 \"테이블\", 관계(Relationship)는 \"연관\"
2. **\"튜플 순서가 의미 있다\"** → ✗ 무의미
3. **\"카디널리티 = 컬럼 수\"** → ✗ **행 수**, 차수가 컬럼 수
4. **\"NoSQL은 SQL을 못 쓴다\"** → ✗ Not Only SQL
5. **\"OLTP는 분석에 좋다\"** → ✗ 분석은 OLAP
6. **\"RDB는 ACID를 보장 안 함\"** → ✗ ACID가 RDB의 핵심 강점
7. **\"코드의 12법칙은 모든 RDBMS가 완벽 준수\"** → ✗ 일부만 준수

## 10. 📝 기출 출제 패턴

### 패턴 A: 용어 정의 ⭐
> \"카디널리티의 의미는?\" → 튜플(행)의 수

### 패턴 B: 차수 vs 카디널리티
> \"차수(Degree)와 카디널리티(Cardinality)의 차이는?\"
- 차수 = 컬럼 수
- 카디널리티 = 행 수

### 패턴 C: RDB의 성질
> \"관계형 모델의 성질이 아닌 것은?\"
- 무순서·유일성·원자값에 \"순서 보장\" 같은 가짜 답

### 패턴 D: OLTP vs OLAP
> \"OLTP의 특징으로 옳은 것은?\"
- 짧은 트랜잭션, 운영 데이터, 정규화

## 11. 📌 시험 직전 체크

> **핵심 메커니즘 + 빈출 포인트**

✅ **6대 용어 = 릴튜속도차카**:
   - 릴레이션 = 테이블
   - 튜플 = 행
   - 속성 = 컬럼
   - 도메인 = 값 범위
   - **차수** = 컬럼 수
   - **카디널리티** = 행 수 ⭐

✅ **RDB 성질**: 유일성, 무순서(행/열), 속성명 유일, 원자값

✅ **코드의 12법칙** = E.F. Codd 제안 (RDBMS 조건)

✅ **OLTP**: 짧은 트랜잭션, 운영 (주문·계좌)
✅ **OLAP**: 분석, 누적 데이터 (BI·DW)

✅ **RDB vs NoSQL**:
   - RDB: 표·SQL·ACID·수직 확장
   - NoSQL: 다양·유연·BASE·수평 확장

✅ **빈출**: \"카디널리티 = 행 수\"

✅ **빈출**: \"차수 = 컬럼 수\"
