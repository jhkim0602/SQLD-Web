## 1. 데이터 모델링이란?

현실 세계의 업무를 **데이터로 표현**하기 위해 추상화·단순화·명확화하는 과정.

> 💡 **모델링 = 약속**. 개발자·기획자·DBA가 같은 그림을 보기 위한 청사진.

## 2. 데이터 모델링의 3가지 관점 ⭐⭐ (빈출)

| # | 관점 | 질문 | 산출물 |
|---|---|---|---|
| 1 | **데이터 관점 (What)** | 무엇을 관리하는가? | **ERD** |
| 2 | **프로세스 관점 (How)** | 어떻게 처리되는가? | DFD |
| 3 | **상관 관점 (Interaction)** | 데이터와 프로세스의 영향은? | CRUD Matrix |

> 🔑 **암기법: "데프상"** (데이터·프로세스·상관)

> ⚠️ \"사용자 관점(Who)\"은 3대 관점에 **포함되지 않음** (함정)

## 3. 데이터 모델링 3단계 ⭐⭐⭐ (최빈출)

```
개념 → 논리 → 물리
추상      정규화    DBMS 종속
```

| 단계 | 산출물 | 특징 | 추상화 |
|---|---|---|---|
| **개념적 모델링** | 개략 ERD | 핵심 엔터티·관계 도출, 전사적 관점 | 가장 추상 |
| **논리적 모델링** | 정규화 ERD | 키·관계 정의, **DBMS 독립적** | 중간 |
| **물리적 모델링** | 테이블·인덱스 | DBMS에 맞춤, 반정규화, 인덱스 | 가장 구체 |

> 🔑 **암기법: "개논물"** (개념·논리·물리)

### 단계별 주요 활동

| 단계 | 활동 |
|---|---|
| 개념 | 주제 영역 도출 → 핵심 엔터티 식별 → 개략 관계 |
| 논리 | 속성 상세화 → 정규화 → PK/FK 확정 |
| 물리 | 테이블·컬럼·인덱스·파티션 설계, 반정규화 적용 |

## 4. 좋은 데이터 모델의 특징 ⭐ (빈출)

| # | 특징 | 설명 |
|---|---|---|
| 1 | **완전성** | 업무에서 필요한 모든 데이터 표현 |
| 2 | **중복 배제** | 동일 데이터를 여러 곳에 저장 X |
| 3 | **업무 규칙 반영** | 업무 규칙을 모델에 명확히 |
| 4 | **데이터 재사용** | 통합된 데이터로 재사용 ↑ |
| 5 | **의사소통** | 관계자 간 소통 도구 |
| 6 | **통합성** | 전사 데이터의 일관성 |

> 🔑 **암기법: "완중업재의통"**

## 5. 스키마 3계층 (ANSI/SPARC) ⭐⭐ (빈출)

| 계층 | 관점 | 내용 |
|---|---|---|
| **외부 스키마 (External)** | 사용자별 | 응용·뷰 (View) — 각 사용자가 보는 부분 |
| **개념 스키마 (Conceptual)** | DBA · 전체 | 통합 데이터베이스 구조 |
| **내부 스키마 (Internal)** | 물리 | 저장 구조, 인덱스, 파일 |

```
[ 사용자 A ] [ 사용자 B ]   ← 외부 스키마 (각자의 뷰)
        ↓        ↓
    [ 개념 스키마 ]          ← 전사 통합 구조
            ↓
    [ 내부 스키마 ]          ← 디스크 저장 구조
```

> 🔑 **암기법: "외개내"** (외부·개념·내부)

### 데이터 독립성

3계층 구조의 **핵심 목적**.

| 독립성 | 의미 |
|---|---|
| **논리적 독립성** | 개념 스키마 변경이 외부 스키마에 영향 X |
| **물리적 독립성** | 내부 스키마 변경이 개념 스키마에 영향 X |

## 6. 슈퍼타입/서브타입 (Super/Sub Type) ⭐⭐

상속 관계 모델링. 공통 속성을 슈퍼타입에, 특수 속성을 서브타입에.

```
[직원] (슈퍼타입)
   |
   ├── [정규직] (서브타입)
   └── [계약직] (서브타입)
```

### 물리 변환 3가지 방법

| 방법 | 설명 | 적합 |
|---|---|---|
| **1. OneToOne (개별)** | 슈퍼·서브 각각 테이블 | 서브별 처리량이 매우 다를 때 |
| **2. Plus (Sub Type)** | 슈퍼+서브로 분리 | 서브별 처리 + 공통 처리 둘 다 |
| **3. Single (One Table)** | 하나의 통합 테이블 + 구분 컬럼 | 데이터량 적고 통합 조회 잦음 |

> 🔑 **암기법: "원플싱"** (OneToOne · Plus · Single)

## 7. ERD 표기법 (IE 표기)

```
┌──────────┐         ┌──────────┐
│  엔터티1  │──────<│  엔터티2  │
└──────────┘  1:M    └──────────┘
```

| 기호 | 의미 |
|---|---|
| `┤` | 1 (정확히 하나) |
| `<` (까마귀발) | M (여러 개) |
| `○` | 0 (선택) |
| `┼` | 1 이상 |
| 실선 | 식별 관계 |
| 점선 | 비식별 관계 |

## 8. ⚠️ 자주 틀리는 함정

1. **\"사용자 관점이 모델링 3대 관점\"** → ✗ (데이터·프로세스·상관만)
2. **\"논리적 모델링은 DBMS 종속\"** → ✗ **독립적**
3. **\"개념적 모델링이 가장 구체적\"** → ✗ 가장 추상
4. **\"3단계 순서: 논리 → 개념 → 물리\"** → ✗ **개념 → 논리 → 물리**
5. **\"외부 스키마 = 내부 저장 구조\"** → ✗ 사용자별 뷰
6. **\"슈퍼타입은 추상 클래스라 테이블로 만들 수 없다\"** → ✗ Single Type에선 통합

## 9. 📝 기출 출제 패턴

### 패턴 A: 3대 관점
> \"데이터 모델링의 3가지 관점 중 하나가 아닌 것은?\"
- 사용자/관리자/시간 관점 등이 가짜 답

### 패턴 B: 모델링 단계 순서
> \"데이터 모델링 단계를 올바르게 나열한 것은?\"
- 개념 → 논리 → 물리 (역순 함정 출제)

### 패턴 C: 스키마 3계층
> \"각 사용자가 접근하는 부분에 해당하는 스키마는?\"
- 외부 스키마가 정답

### 패턴 D: 슈퍼타입 변환
> \"슈퍼/서브타입 변환 방법이 아닌 것은?\"
- Multi Type, Hybrid Type 같은 가짜 답

| 항목 | 암기법 |

## 11. 📌 시험 합격 핵심 요약

> **시험장 입실 5분 전 점검**

✅ **3대 관점 = 데프상** (데이터·프로세스·상관)
   - 사용자(Who)는 ✗

✅ **3단계 = 개논물** (개념→논리→물리)
   - 추상 → 구체
   - 논리는 **DBMS 독립**

✅ **좋은 모델 = 완중업재의통**

✅ **스키마 3계층 = 외개내**
   - 외부 = 사용자 뷰
   - 개념 = 전사 통합
   - 내부 = 물리 저장

✅ **데이터 독립성**:
   - 논리적 = 개념↔외부
   - 물리적 = 내부↔개념

✅ **슈퍼/서브타입 = 원플싱**

✅ **함정**: \"논리적 모델링은 DBMS 종속\" → ✗
