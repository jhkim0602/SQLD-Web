## 데이터 모델링의 3가지 관점

| 관점 | 질문 | 산출물 |
|---|---|---|
| **데이터(What)** | 무엇을 관리하나? | ERD |
| **프로세스(How)** | 어떻게 처리되나? | DFD |
| **상관(Interaction)** | 데이터와 프로세스의 영향은? | CRUD Matrix |

> 사용자(Who)는 3대 관점에 포함되지 않는다.

## 데이터 모델링 3단계

```
개념 → 논리 → 물리
(추상)  (정규화)  (DBMS 종속)
```

| 단계 | 특징 |
|---|---|
| **개념적 모델링** | 추상적·전사적. 핵심 엔터티 도출. ERD 초안. |
| **논리적 모델링** | 정규화, 키·관계 정의. DBMS 독립적. |
| **물리적 모델링** | 실제 DBMS에 맞춰 테이블·인덱스·파티션·반정규화 적용. |

**암기 팁**: **개·논·물**

## 데이터 모델의 좋은 특징

1. **완전성**: 업무에서 필요한 모든 데이터를 표현
2. **중복 배제**: 동일 데이터를 여러 곳에 저장하지 않음
3. **업무 규칙 반영**
4. **데이터 재사용성**
5. **의사소통 도구**
6. **통합성**

## ERD 표기법 (IE 표기)

- **사각형**: 엔터티
- **원**: 속성 (또는 사각형 안에 나열)
- **선**: 관계
- **선의 끝**:
  - 일자(|): 1
  - 까마귀발(◇): M
  - 동그라미(○): 0 (선택)

## 스키마 3계층

| 계층 | 설명 |
|---|---|
| **외부 스키마** | 사용자별 뷰 |
| **개념 스키마** | 통합 데이터 구조 |
| **내부 스키마** | 물리적 저장 구조 |
