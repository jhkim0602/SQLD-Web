## 1. 정의

**속성(Attribute)**은 엔터티에서 관리할 수 있는 가장 작은 데이터의 의미 단위이다. 더 이상 분리할 수 없으며(원자성), 인스턴스의 특징을 표현한다.

> 💡 엔터티는 \"무엇\"을 관리, 속성은 \"어떤 정보\"를 관리.

```
사원 엔터티
├── 사번    (식별자, PK)
├── 이름    (기본 속성)
├── 입사일  (기본 속성)
├── 부서ID  (외래 속성, FK)
└── 근속연수 (파생 속성: SYSDATE - 입사일)
```

## 2. 속성의 분류 (3가지 기준) ⭐⭐⭐

### 2-1. 특성에 따른 분류

| 분류 | 설명 | 예시 |
|---|---|---|
| **기본 속성 (Basic)** | 업무 분석에서 도출된 본래의 속성 | 이름, 생년월일, 주소 |
| **설계 속성 (Designed)** | 모델링 과정에서 인위적으로 부여 | 상품코드(시퀀스), 사번 |
| **파생 속성 (Derived)** | 다른 속성으로부터 계산·유도 | 총금액=단가×수량, 나이=SYSDATE-생년월일 |

> 🔑 **암기법: "기설파"** (기본·설계·파생)

> ⚠️ **파생 속성은 가능한 적게**. 갱신 시 정합성 관리 부담.

### 2-2. 구성 방식에 따른 분류

| 분류 | 설명 |
|---|---|
| **PK 속성** | 주식별자가 되는 속성 |
| **FK 속성** | 다른 엔터티와 관계로 가져온 속성 |
| **일반 속성** | PK도 FK도 아닌 그 외 속성 |

### 2-3. 분해 가능 여부에 따른 분류

| 분류 | 설명 | 예시 |
|---|---|---|
| **단순 속성 (Simple)** | 더 이상 분해 불가 | 이름, 사번 |
| **복합 속성 (Composite)** | 여러 의미값으로 구성 | 주소 = 시 + 구 + 동 |
| **단일값 속성 (Single-valued)** | 한 인스턴스당 한 값 | 생년월일 |
| **다중값 속성 (Multi-valued)** | 한 인스턴스가 여러 값 | 취미, 전화번호 |

> 🔑 **암기법: "단복단다"** (단순·복합·단일값·다중값)

> ⚠️ **다중값 속성은 별도 엔터티로 분리** (1NF 만족 위해)

## 3. 도메인 (Domain)

속성이 가질 수 있는 값의 범위·형식·제약.

| 구성 요소 | 예시 |
|---|---|
| 데이터 타입 | VARCHAR2(50), NUMBER(10) |
| 길이 | 최대 50자 |
| 허용 값 | `CHECK (gender IN ('M', 'F'))` |
| 기본값 | `DEFAULT SYSDATE` |
| NULL 허용 | NOT NULL |

```sql
CREATE TABLE emp (
  empno NUMBER(4) PRIMARY KEY,           -- 도메인: 4자리 숫자
  ename VARCHAR2(20) NOT NULL,           -- 도메인: 20자 이내 문자, NULL 불허
  gender CHAR(1) CHECK (gender IN ('M', 'F')),  -- 도메인: M 또는 F
  hiredate DATE DEFAULT SYSDATE,
  sal NUMBER(8, 2) CHECK (sal >= 0)
);
```

## 4. 속성의 표기법

ERD에서 속성:
- **#**: 주식별자 (PK)
- **\***: NOT NULL (필수 속성)
- **○**: NULL 허용 (선택 속성)
- **(FK)**: 외래 식별자

```
사원
─────────
# 사번
* 이름
○ 매니저ID (FK)
* 입사일
○ 퇴사일
```

## 5. ⚠️ 자주 틀리는 함정

1. **\"PK 속성, FK 속성, 일반 속성\"은 \"구성 방식\" 분류 ○** — 종종 \"특성 분류\"라 함정으로 출제
2. **\"파생 속성은 항상 저장하여 조회 성능을 우선\"** → ✗ 갱신 시 정합성 부담
3. **\"다중값 속성을 한 칸에 콤마로 저장\"** → ✗ 1NF 위반
4. **\"속성과 도메인은 같은 의미\"** → ✗ 도메인은 속성의 \"값 범위\"
5. **\"한 속성은 하나의 도메인을 가진다\"** → ○ 정답
6. **\"속성은 분해 가능하다\"** → ✗ \"가장 작은 정보 단위\"

## 6. 📝 기출 출제 패턴

### 패턴 A: 분류 기준
> \"다음 중 속성의 분류로 옳지 않은 것은?\"
- 3가지 분류 기준 중 하나를 다른 분류와 혼동시키는 함정
- \"PK/FK는 특성 분류\" ← 거짓 (구성방식 분류)

### 패턴 B: 도메인
> \"도메인(Domain)에 대한 설명으로 옳은 것은?\"
- \"엔터티 영역\", \"DBA 권한\" 등 헷갈리는 선택지

### 패턴 C: 파생 속성
> \"파생 속성에 대한 설명으로 옳지 않은 것은?\"
- \"가능한 많이 정의\", \"항상 저장\" 등이 오답

## 7. 🔑 암기법 종합

| 분류 기준 | 암기법 |
|---|---|
| 특성 | **기설파** (기본·설계·파생) |
| 구성 방식 | **PFG** (PK·FK·일반/General) |
| 분해 여부 | **단복단다** (단순·복합·단일·다중) |

## 8. 📌 시험 합격 핵심 요약

> **시험장 입실 5분 전 점검**

✅ **속성 = 가장 작은 의미 단위** (원자성)

✅ **3대 분류**:
   - 특성 → **기설파** (기본·설계·파생)
   - 구성 → **PK / FK / 일반**
   - 분해 → **단순 / 복합 / 단일값 / 다중값**

✅ **도메인** = 속성의 값 범위 + 타입 + 제약

✅ **파생 속성은 적게**, 정합성 관리 부담

✅ **다중값 속성**은 별도 엔터티 (1NF)

✅ **PK는 NULL 불가**, 일반·FK는 NULL 가능
