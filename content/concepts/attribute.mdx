## 1. 속성이란?

**속성(Attribute)**은 엔터티가 가지는 **세부 정보 항목**으로, 업무에서 필요한 가장 작은 의미의 데이터 단위이다. 더 이상 분리할 수 없는 **원자값**을 갖는다.

> 💡 엔터티가 \"무엇\"인지를 정의, 속성은 \"어떤 정보\"인지를 정의.

```
[사원] 엔터티
├─ 사번      (식별자, PK)
├─ 이름      (기본 속성)
├─ 입사일    (기본 속성)
├─ 부서ID    (외래 속성, FK)
├─ 직급코드  (설계 속성)
└─ 근속연수  (파생 속성: SYSDATE - 입사일)
```

## 2. 속성의 3대 특성

| 특성 | 설명 |
|---|---|
| **단일 의미** | 하나의 속성은 하나의 의미만 가짐 |
| **원자성 (Atomic)** | 더 이상 분리할 수 없는 최소 단위 |
| **단일 값** | 한 인스턴스는 속성당 하나의 값 (기본) |

> ⚠️ **원자성 위반**: 한 컬럼에 콤마로 여러 값 → 1NF 위반

## 3. 속성의 분류 (3가지 기준) ⭐⭐⭐

### 3-1. 특성에 따른 분류

| 분류 | 설명 | 예시 |
|---|---|---|
| **기본 속성 (Basic)** | 업무 분석으로 도출된 본래의 속성 | 이름, 생년월일, 주소 |
| **설계 속성 (Designed)** | 모델링 과정에서 인위적으로 부여 | 상품코드(시퀀스), 사번 |
| **파생 속성 (Derived)** | 다른 속성으로부터 계산·유도 | 총금액=단가×수량, 나이=SYSDATE-생년월일 |

> 🔑 **암기법: \"기설파\"** (기본·설계·파생)

#### 파생 속성을 적게 정의해야 하는 이유

```sql
-- 파생 속성을 저장하는 경우의 문제
주문(주문번호, 수량, 단가, 총금액)
   - 단가나 수량이 변경되면 총금액도 갱신 필요
   - 동기화 누락 시 데이터 정합성 깨짐

-- 권장: 파생 속성은 계산으로 (또는 뷰)
SELECT 주문번호, 수량 * 단가 AS 총금액 FROM 주문;
```

> ⚠️ **파생 속성은 가능한 적게**. 정합성 부담이 크다.

### 3-2. 구성 방식에 따른 분류

| 분류 | 설명 |
|---|---|
| **PK 속성** | 주식별자가 되는 속성 |
| **FK 속성** | 다른 엔터티와의 관계에서 가져온 속성 |
| **일반 속성** | PK도 FK도 아닌 그 외 |

```
[주문] 엔터티
- 주문번호 (PK 속성)
- 고객ID (FK 속성, 고객 엔터티 참조)
- 주문일자 (일반 속성)
- 총액 (일반 속성)
```

### 3-3. 분해 가능 여부에 따른 분류

| 분류 | 설명 | 예시 |
|---|---|---|
| **단순 속성 (Simple)** | 더 이상 분해 불가 | 이름, 사번 |
| **복합 속성 (Composite)** | 여러 의미값으로 구성 | 주소 = 시 + 구 + 동 |
| **단일값 속성 (Single-valued)** | 한 인스턴스당 한 값 | 생년월일 |
| **다중값 속성 (Multi-valued)** | 한 인스턴스가 여러 값 | 취미, 전화번호 |

> 🔑 **암기법: \"단복단다\"** (단순·복합·단일값·다중값)

#### 다중값 속성의 처리

> ⚠️ **다중값 속성은 별도 엔터티로 분리** (1NF 만족 위해)

```sql
-- ✗ 1NF 위반
사원(사번, 이름, 자격증)
  → 자격증 컬럼에 'OCP, SQLD, ADsP' 같은 식

-- ✓ 별도 엔터티로 분리
사원(사번, 이름)
사원_자격증(사번 FK, 자격증)
```

## 4. 도메인 (Domain)

**도메인(Domain)**은 속성이 가질 수 있는 **값의 범위·형식·제약**의 집합이다.

| 구성 요소 | 예시 |
|---|---|
| **데이터 타입** | NUMBER(10), VARCHAR2(50), DATE |
| **길이** | 최대 50자 |
| **허용 값** | `CHECK (gender IN ('M', 'F'))` |
| **기본값** | `DEFAULT SYSDATE` |
| **NULL 허용 여부** | NOT NULL |

```sql
CREATE TABLE emp (
  empno    NUMBER(4) PRIMARY KEY,                       -- 4자리 숫자
  ename    VARCHAR2(20) NOT NULL,                       -- 20자, NULL 불허
  gender   CHAR(1) CHECK (gender IN ('M', 'F')),        -- M/F만
  hiredate DATE DEFAULT SYSDATE,                        -- 기본값 = 현재
  sal      NUMBER(8, 2) CHECK (sal >= 0),               -- 음수 금지
  email    VARCHAR2(100) CHECK (email LIKE '%@%')       -- 형식 검증
);
```

### 도메인의 의의

- 데이터 무결성 보장
- 비즈니스 규칙을 데이터 레벨에서 강제
- 컬럼 정의 표준화

## 5. NULL 속성

NULL은 \"값이 없음\" 또는 \"알 수 없음\"을 의미한다. 0이나 빈 문자열과 다르다.

### NULL을 허용할지 결정 기준

| 속성 | NULL 허용? |
|---|---|
| **주식별자 (PK)** | **✗ 불허** (개체 무결성) |
| **NOT NULL 제약 속성** | ✗ |
| **외래 식별자 (FK)** | **○ 허용 가능** (선택 관계) |
| **일반 선택 속성** | ○ |

### NULL 처리 시 주의

```sql
-- ✗ 항상 UNKNOWN
WHERE comm = NULL

-- ✓ 올바른 NULL 비교
WHERE comm IS NULL
WHERE comm IS NOT NULL

-- 사칙연산 시 NULL 전파
1 + NULL = NULL          -- ✗
NVL(comm, 0) + 1 = 1     -- ✓ NULL 대체 후 계산
```

## 6. 속성의 표기법 (ERD)

ERD에서 속성 표기 규칙:

| 기호 | 의미 |
|---|---|
| **#** | 주식별자 (PK) |
| **\*** | NOT NULL (필수 속성) |
| **○** | NULL 허용 (선택 속성) |
| **(FK)** | 외래 식별자 |

```
[사원]
─────────
# 사번      ← PK
* 이름      ← NOT NULL
○ 매니저ID (FK)  ← NULL 허용, FK
* 입사일    ← NOT NULL
○ 퇴사일    ← NULL 허용
```

## 7. 속성 도출 시 고려사항

1. **속성명**: 업무 용어 사용, 약어 지양
2. **유일성**: 같은 이름 속성 둘 X
3. **단일 의미**: 하나의 속성은 하나의 의미
4. **원자성**: 더 이상 분해 불가
5. **NULL 허용 여부**: 업무 규칙에 따라 결정
6. **도메인 정의**: 타입·길이·범위 명확히
7. **파생 여부 검토**: 저장 vs 계산 trade-off

## 8. 속성 명명 규칙

| # | 규칙 | 예 |
|---|---|---|
| 1 | 의미 명확 | `이름` ○, `data` ✗ |
| 2 | 일관성 | 모든 엔터티에서 동일 명명 |
| 3 | 유일성 | 엔터티 안에 동명 X |
| 4 | 약어 지양 | `생년월일` ○, `bday` ✗ |
| 5 | 보편 용어 | 사내에서 통용되는 단어 |

## 9. ⚠️ 자주 틀리는 함정

1. **\"PK/FK는 특성 분류\"** → ✗ \"구성방식\" 분류
2. **\"파생 속성은 항상 저장해 조회 성능 우선\"** → ✗ 갱신 시 정합성 부담
3. **\"다중값 속성을 한 칸에 콤마로 저장\"** → ✗ 1NF 위반
4. **\"속성과 도메인은 같은 의미\"** → ✗ 도메인은 속성의 값 범위
5. **\"한 속성은 여러 도메인을 가질 수 있다\"** → ✗ 1개만
6. **\"속성은 분해 가능하다\"** → ✗ 가장 작은 정보 단위 (원자성)
7. **\"NULL = 0\"** → ✗ \"값 없음\"
8. **\"기본 속성은 PK\"** → ✗ 기본 속성과 PK는 다른 분류 축

## 10. 📝 기출 출제 패턴

### 패턴 A: 분류 구분 ⭐ 빈출
> \"속성의 분류로 옳지 않은 것은?\"
- 3가지 분류 기준을 헷갈리게 배치
- \"PK/FK = 특성 분류\" ← 거짓 (구성방식)

### 패턴 B: 도메인 정의
> \"도메인에 대한 설명으로 옳은 것은?\"
- \"엔터티 영역\", \"DBA 권한\" 같은 가짜 답

### 패턴 C: 파생 속성
> \"파생 속성에 대한 설명으로 옳지 않은 것은?\"
- \"가능한 많이 정의\", \"항상 저장\" 등이 오답

### 패턴 D: 다중값 처리
> \"다중값 속성의 가장 적절한 처리는?\"
- 별도 엔터티로 분리 (정답)

## 11. 📌 ERD·모델링 한눈

> **분류 · ERD 표기 · 명명 규칙**

✅ **속성 = 가장 작은 의미 단위** (원자성)

✅ **3대 분류**:
   - **특성**: 기본 · 설계 · 파생 (**기설파**)
   - **구성**: PK · FK · 일반
   - **분해**: 단순 · 복합 · 단일값 · 다중값

✅ **도메인** = 속성의 값 범위 + 타입 + 제약 + 기본값 + NULL 여부

✅ **파생 속성**:
   - 다른 속성에서 계산/유도
   - **가능한 적게** 정의
   - 저장 시 정합성 부담 ↑

✅ **다중값 속성** → 별도 엔터티로 분리 (1NF)

✅ **NULL 허용 표**:
   - PK ✗ / UNIQUE ○ / FK ○ / NOT NULL ✗

✅ **속성 ERD 기호**: `#` PK / `*` NOT NULL / `○` NULL OK / (FK)

✅ **빈출**: \"PK/FK는 구성방식 분류\" (특성 분류 아님)

### 🔑 암기법 정리

| 분류 기준 | 암기법 |
|---|---|
| 특성 | **기설파** (기본·설계·파생) |
| 구성 방식 | **PFG** (PK·FK·일반/General) |
| 분해 여부 | **단복단다** (단순·복합·단일·다중) |
| 도메인 5요소 | \"타·길·값·기·N\" (타입·길이·값범위·기본값·NULL) |
