## 뷰란?

**뷰(View)**는 하나 이상의 테이블이나 다른 뷰에서 도출되는 **가상의 테이블**이다. 실제 데이터를 저장하지 않고 **SELECT 쿼리만 저장**한다.

```sql
CREATE OR REPLACE VIEW dept_summary AS
SELECT deptno, COUNT(*) AS cnt, AVG(sal) AS avg_sal
FROM emp
GROUP BY deptno;

-- 일반 테이블처럼 사용 가능
SELECT * FROM dept_summary WHERE avg_sal > 2000;
```

## 장점

| 장점 | 설명 |
|---|---|
| **복잡성 은폐** | 복잡한 조인·집계를 단순한 SELECT로 |
| **재사용성** | 한 번 정의 → 여러 곳에서 사용 |
| **보안** | 특정 컬럼·행만 노출 (민감 정보 차단) |
| **독립성** | 기반 테이블 변경 시 뷰만 수정해 흡수 |

## 단점

- **성능**: 매번 정의 쿼리가 실행됨 (저장된 결과 X)
- **갱신 제약**: 모든 뷰가 INSERT/UPDATE/DELETE 가능한 것은 아님

## 갱신 가능 뷰의 조건

> ⚠️ 다음 중 하나라도 포함되면 **갱신 불가**

- 집계 함수 (SUM, COUNT, AVG ...)
- `GROUP BY` 절
- `DISTINCT`
- `HAVING`
- 윈도우 함수
- 표현식·함수로 만든 컬럼 (예: `sal * 12`)
- 집합 연산자 (UNION 등)

```sql
-- ✗ 갱신 불가 (집계함수 포함)
CREATE VIEW v_avg AS
SELECT deptno, AVG(sal) avg_sal FROM emp GROUP BY deptno;

-- ✓ 갱신 가능 (단순 컬럼만)
CREATE VIEW v_emp AS
SELECT empno, ename, sal FROM emp WHERE deptno = 10;
```

## WITH CHECK OPTION

뷰를 통해 INSERT/UPDATE한 데이터가 뷰의 WHERE 조건을 만족해야 함을 강제.

```sql
CREATE VIEW v_dept10 AS
SELECT * FROM emp WHERE deptno = 10
WITH CHECK OPTION;

INSERT INTO v_dept10 VALUES (..., 20);  -- 에러! deptno=20은 뷰 조건 위반
```

## WITH READ ONLY

뷰를 통한 모든 DML을 차단.

```sql
CREATE VIEW v_readonly AS SELECT * FROM emp
WITH READ ONLY;

UPDATE v_readonly SET sal = 0;  -- 에러
```

## 일반 뷰 vs 구체화 뷰 (Materialized View)

| 구분 | 일반 뷰 | 구체화 뷰 |
|---|---|---|
| **데이터 저장** | X (쿼리만) | **O (실제 저장)** |
| **성능** | 매번 재실행 | 빠름 (조회) |
| **갱신** | 자동 (기반 테이블 따라감) | 수동/스케줄 (REFRESH) |
| **공간** | 거의 0 | 데이터만큼 차지 |
| **용도** | 단순화, 보안 | 집계·DW |

```sql
-- 구체화 뷰
CREATE MATERIALIZED VIEW mv_dept_summary
BUILD IMMEDIATE
REFRESH COMPLETE ON DEMAND
AS
SELECT deptno, COUNT(*) cnt, AVG(sal) avg_sal
FROM emp GROUP BY deptno;
```

## 시험 빈출 포인트

> 📌 **자주 출제**
> - 뷰는 **실데이터를 저장하지 않는다** (구체화 뷰 제외)
> - 갱신 가능 뷰의 조건 (집계·DISTINCT·GROUP BY 시 불가)
> - `WITH CHECK OPTION`의 동작
> - `OR REPLACE` 옵션으로 기존 뷰 수정 가능
> - 뷰 제거: `DROP VIEW`
