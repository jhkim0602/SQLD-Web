## 1. 정의

**뷰(View)**는 하나 이상의 테이블이나 다른 뷰에서 도출되는 **가상의 테이블**. 실제 데이터를 저장하지 않고 **SELECT 쿼리만 저장**.

```sql
CREATE OR REPLACE VIEW dept_summary AS
SELECT deptno, COUNT(*) AS cnt, AVG(sal) AS avg_sal
FROM emp
GROUP BY deptno;

SELECT * FROM dept_summary WHERE avg_sal > 2000;
```

## 2. 장점 ⭐

| 장점 | 설명 |
|---|---|
| **복잡성 은폐** | 복잡한 조인·집계를 단순 SELECT로 |
| **재사용성** | 한 번 정의 → 여러 곳에서 사용 |
| **보안** | 특정 컬럼·행만 노출 |
| **독립성** | 기반 테이블 변경 시 뷰만 수정 |

> 🔑 **암기법: "복재보독"** (복잡 은폐·재사용·보안·독립성)

## 3. 단점

- **성능**: 매번 정의 쿼리 실행 (캐싱 없음)
- **갱신 제약**: 모든 뷰가 갱신 가능 X

## 4. 갱신 가능 뷰의 조건 ⭐⭐⭐ (시험 빈출)

> ⚠️ 다음 중 하나라도 포함되면 **갱신 불가**

| 포함 요소 | 갱신 |
|---|---|
| 집계 함수 (SUM, COUNT, AVG ...) | ✗ |
| `GROUP BY` | ✗ |
| `DISTINCT` | ✗ |
| `HAVING` | ✗ |
| 윈도우 함수 | ✗ |
| 표현식·함수 컬럼 (`sal * 12`) | ✗ |
| 집합 연산자 (UNION 등) | ✗ |
| ROWNUM | ✗ |

> 🔑 **암기법: "집그디 해윈 표집ROW"** (집계·GROUP·DISTINCT·HAVING·윈도우·표현식·집합·ROWNUM)

```sql
-- ✗ 갱신 불가
CREATE VIEW v_avg AS
SELECT deptno, AVG(sal) avg_sal FROM emp GROUP BY deptno;

-- ✓ 갱신 가능
CREATE VIEW v_emp AS
SELECT empno, ename, sal FROM emp WHERE deptno = 10;
```

## 5. WITH CHECK OPTION ⭐

뷰를 통해 INSERT/UPDATE한 데이터가 **뷰의 WHERE 조건**을 만족해야 함을 강제.

```sql
CREATE VIEW v_dept10 AS
SELECT * FROM emp WHERE deptno = 10
WITH CHECK OPTION;

INSERT INTO v_dept10 VALUES (..., 20);  -- ✗ 에러
INSERT INTO v_dept10 VALUES (..., 10);  -- ✓
```

## 6. WITH READ ONLY

뷰를 통한 모든 DML 차단.

```sql
CREATE VIEW v_readonly AS SELECT * FROM emp
WITH READ ONLY;

UPDATE v_readonly SET sal = 0;  -- 에러
```

## 7. 일반 뷰 vs 구체화 뷰 ⭐

| | 일반 뷰 | 구체화 뷰 (Materialized View) |
|---|---|---|
| **데이터 저장** | ✗ (쿼리만) | **○ (실제 저장)** |
| **성능** | 매번 재실행 | 빠름 |
| **갱신** | 자동 | 수동/스케줄 (REFRESH) |
| **공간** | 거의 0 | 데이터 크기 |
| **용도** | 단순화·보안 | 집계·DW |

```sql
CREATE MATERIALIZED VIEW mv_dept_summary
BUILD IMMEDIATE
REFRESH COMPLETE ON DEMAND
AS
SELECT deptno, COUNT(*), AVG(sal) FROM emp GROUP BY deptno;
```

### REFRESH 모드 ⭐

| 모드 | 동작 | 적합 |
|---|---|---|
| `COMPLETE` | 전체 재계산 | 데이터 작거나 정합성 우선 |
| `FAST` | 변경분만 반영 (MV 로그 필요) | 데이터 큼, 빈번 갱신 |
| `FORCE` (기본) | FAST 가능하면 FAST, 아니면 COMPLETE | 일반 |
| `NEVER` | 자동 갱신 X | 수동 관리 |

| 시점 | 의미 |
|---|---|
| `ON COMMIT` | 기반 테이블 트랜잭션 커밋 시 자동 |
| `ON DEMAND` (기본) | `DBMS_MVIEW.REFRESH` 수동 호출 |

## 8. 일반 뷰 vs 인라인 뷰 vs 구체화 뷰

| 종류 | 정의 위치 | 데이터 저장 | 영속성 | 용도 |
|---|---|---|---|---|
| **일반 뷰** | `CREATE VIEW` (객체) | ✗ | 영구 | 보안·복잡성 은폐 |
| **인라인 뷰** | `FROM (...)` (쿼리 안) | ✗ | 쿼리 한정 | 임시 결과 집합 |
| **구체화 뷰** | `CREATE MATERIALIZED VIEW` | ✓ | 영구 | 집계 캐싱·DW |

```sql
-- 인라인 뷰 (FROM 절 서브쿼리)
SELECT *
FROM (SELECT deptno, AVG(sal) avg_sal FROM emp GROUP BY deptno) d
WHERE d.avg_sal > 2000;
```

> 📌 시험에서 \"인라인 뷰는 영구 객체이다\" → **거짓** (쿼리 종료 시 사라짐)

## 9. ⚠️ 자주 틀리는 함정

1. **\"뷰는 실데이터 저장\"** → ✗ (구체화 뷰만)
2. **\"모든 뷰는 갱신 가능\"** → ✗
3. **\"WITH CHECK OPTION으로 SELECT 제한\"** → ✗ INSERT/UPDATE만
4. **\"뷰 변경은 DROP만\"** → ✗ `CREATE OR REPLACE`
5. **\"GROUP BY 뷰도 갱신 가능\"** → ✗
6. **\"인라인 뷰는 객체로 영구 저장\"** → ✗ 쿼리 안에서만 유효
7. **\"구체화 뷰는 자동으로 항상 최신\"** → △ REFRESH 정책에 따름

## 10. 📝 기출 출제 패턴

### 패턴 A: 갱신 불가 조건 ⭐ 최빈출
> \"갱신 가능 뷰의 조건이 아닌 것은?\"
- 함정 선택지: 집계 / GROUP BY / DISTINCT / HAVING / 윈도우 / 표현식 / 집합 / ROWNUM

### 패턴 B: WITH CHECK OPTION
> \"역할은?\"
- 정답: 뷰의 WHERE 조건 위반하는 INSERT/UPDATE 차단

### 패턴 C: 구체화 뷰
> \"실데이터 저장 뷰는?\"
- 정답: Materialized View

### 패턴 D: 일반 vs 인라인 vs 구체화 ⭐
> \"세 종류 뷰의 차이로 옳지 않은 것은?\"

## 11. 📌 실전 치트시트

> **핵심 구문 + 함정 + 빈출 패턴**

✅ **뷰 = 가상 테이블** (쿼리만 저장)

✅ **장점 = 복재보독** (복잡·재사용·보안·독립)

✅ **갱신 불가 조건**: 집계·GROUP BY·DISTINCT·HAVING·윈도우·표현식·집합·ROWNUM 포함 시

✅ **WITH CHECK OPTION** = INSERT/UPDATE 조건 강제

✅ **WITH READ ONLY** = 모든 DML 차단

✅ **구체화 뷰** = 실데이터 저장 (집계·DW용)

✅ **빈출**: \"GROUP BY 뷰는 갱신 ✗\"

### 🔑 암기법 정리

| 뷰 장점 | **복재보독** |

| WITH CHECK | "INSERT/UPDATE 조건 강제" |
| 구체화 뷰 | "실데이터 저장 = 집계·DW용" |
