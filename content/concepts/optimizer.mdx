## 1. 옵티마이저란?

**옵티마이저(Optimizer)**는 SQL을 가장 효율적으로 실행할 방법(실행계획)을 결정하는 DBMS 내부 모듈.

> 💡 옵티마이저 = \"이 쿼리를 어떤 순서로, 어떤 방식으로 처리할까?\" 의 답변자.

## 2. 옵티마이저 종류 ⭐⭐

| 종류 | 설명 | 사용 |
|---|---|---|
| **RBO** (**R**ule-**B**ased **O**ptimizer) | 고정 규칙으로 우선순위 결정 | Oracle 10g 이전 (deprecated) |
| **CBO** (**C**ost-**B**ased **O**ptimizer) | **통계 정보 기반 비용 계산** | 현대 DBMS 표준 |

> 🔑 **암기법**: \"RBO=규칙, CBO=비용(통계)\"

### CBO의 결정 기준

- 테이블 크기 (행 수)
- 인덱스 분포도
- 컬럼 카디널리티
- 메모리·CPU 비용

## 3. JOIN 처리 방식 3종 ⭐⭐⭐

### 3-1. Nested Loop Join (NL Join)

```
for each row in OUTER:
   for each row in INNER where condition:
      join
```

| 특징 | 설명 |
|---|---|
| 선행 테이블 | **소량** |
| 후행 테이블 | **인덱스 있음** |
| 적합 환경 | **OLTP** (응답 빠름) |
| 대용량 | ✗ |

### 3-2. Hash Join

```
phase 1: 작은 쪽으로 hash 테이블 빌드
phase 2: 큰 쪽 순회 → hash probe
```

| 특징 | 설명 |
|---|---|
| 조인 조건 | **등치(=) 전용** |
| 데이터량 | **대용량** |
| 메모리 | 큼 (PGA/work_mem) |
| 인덱스 | 불필요 |

### 3-3. Sort Merge Join

```
phase 1: 양쪽 정렬
phase 2: 정렬된 결과 병합
```

| 특징 | 설명 |
|---|---|
| 조인 조건 | **등치/범위 모두** 가능 |
| 사전 정렬 | 이미 있으면 매우 빠름 |
| 대용량 | ○ |
| 비용 | 정렬 비용 큼 |

### 비교 정리

| | NL | Hash | Sort Merge |
|---|---|---|---|
| 등치 조인 | ✓ | ✓ | ✓ |
| **비등치 조인** | ✓ | **✗** | ✓ |
| 인덱스 필요 | 후행에 ✓ | ✗ | ✗ |
| 대용량 | ✗ | ✓ | ✓ |
| 소량 | ✓ | ✗ | ✗ |

> 🔑 **암기법**: 
> - **NL** = "**Nested(둘러쌈)**, 소량+인덱스"
> - **Hash** = "**=계열, 대량**"
> - **Sort Merge** = "**정렬+범위**"

## 4. 실행계획 (Execution Plan) ⭐

옵티마이저가 결정한 SQL 실행 방법.

```sql
-- Oracle
EXPLAIN PLAN FOR
SELECT * FROM emp e, dept d WHERE e.deptno = d.deptno;

SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY);
```

```
| Id | Operation               | Name | Rows | Cost |
|----|-------------------------|------|------|------|
|  0 | SELECT STATEMENT        |      |   14 |    5 |
|  1 |  HASH JOIN              |      |   14 |    5 |
|  2 |   TABLE ACCESS FULL     | DEPT |    4 |    2 |
|  3 |   TABLE ACCESS FULL     | EMP  |   14 |    2 |
```

### 읽는 순서

> **들여쓰기 깊은 것부터, 같은 깊이면 위→아래**

### 주요 Operation

| Operation | 의미 |
|---|---|
| TABLE ACCESS FULL | 테이블 전체 스캔 |
| TABLE ACCESS BY INDEX ROWID | 인덱스로 ROWID 찾고 테이블 접근 |
| INDEX UNIQUE SCAN | 인덱스 단일 행 |
| INDEX RANGE SCAN | 인덱스 범위 |
| NESTED LOOPS | NL 조인 |
| HASH JOIN | 해시 조인 |
| MERGE JOIN | 정렬 병합 |
| SORT | 정렬 |
| FILTER | 필터링 |

## 5. 옵티마이저 힌트 ⭐

힌트(`/*+ ... */`)로 옵티마이저 결정을 강제 (남용 주의).

```sql
SELECT /*+ FULL(e) */ * FROM emp e;        -- Full Scan 강제
SELECT /*+ INDEX(e idx_emp_sal) */ * FROM emp e WHERE sal > 1000;
SELECT /*+ USE_NL(e d) */ * FROM emp e, dept d WHERE e.deptno = d.deptno;
SELECT /*+ USE_HASH(e d) */ * FROM emp e, dept d WHERE e.deptno = d.deptno;
SELECT /*+ LEADING(d) */ * FROM emp e, dept d WHERE e.deptno = d.deptno;
SELECT /*+ ORDERED */ * FROM emp e, dept d WHERE e.deptno = d.deptno;
```

### 주요 힌트

| 힌트 | 동작 |
|---|---|
| `/*+ FULL(t) */` | Full Scan 강제 |
| `/*+ INDEX(t idx) */` | 특정 인덱스 사용 |
| `/*+ USE_NL(t1 t2) */` | NL 조인 강제 |
| `/*+ USE_HASH(t1 t2) */` | Hash 조인 강제 |
| `/*+ USE_MERGE(t1 t2) */` | Sort Merge 강제 |
| `/*+ LEADING(t) */` | 선행 테이블 지정 |
| `/*+ ORDERED */` | FROM 절 순서대로 조인 |
| `/*+ PARALLEL(t, 4) */` | 병렬 처리 |

## 6. 통계 정보 관리

```sql
-- 테이블 통계 갱신
EXEC DBMS_STATS.GATHER_TABLE_STATS('SCOTT', 'EMP');

-- 스키마 전체
EXEC DBMS_STATS.GATHER_SCHEMA_STATS('SCOTT');
```

통계가 오래되면 옵티마이저가 잘못된 계획 선택 → **주기적 갱신**

## 7. ⚠️ 자주 틀리는 함정

1. **\"RBO가 CBO보다 정확\"** → ✗ 현대는 CBO
2. **\"NL Join은 항상 빠르다\"** → ✗ 대량에서 느림
3. **\"Hash Join은 비등치도 가능\"** → ✗ **등치만**
4. **\"실행계획은 위에서 아래로 읽음\"** → △ **안쪽부터** 읽음
5. **\"힌트는 항상 따라간다\"** → ✗ 옵티마이저가 무시할 수도
6. **\"Full Table Scan은 무조건 나쁘다\"** → ✗ 전체 필요 시 인덱스보다 빠름

## 8. 📝 기출 출제 패턴

### 패턴 A: JOIN 방식 ⭐ 최빈출
> \"선행 테이블의 각 행마다 후행을 조회하는 방식은?\"
- **Nested Loop**

> \"대용량 등치 조인에 가장 적합한 방식은?\"
- **Hash Join**

### 패턴 B: 옵티마이저 종류
> \"RBO와 CBO의 차이는?\"
- 규칙 vs 비용(통계)

### 패턴 C: 실행계획
> \"실행계획에서 TABLE ACCESS FULL의 의미는?\"
- 전체 스캔

### 패턴 D: 힌트
> \"인덱스를 사용하지 않도록 하는 힌트는?\"
- `/*+ FULL(t) */`

## 9. 🔑 암기법 종합

| 항목 | 암기법 |
|---|---|
| 옵티마이저 2종 | **RBO(규칙) vs CBO(비용)** |
| JOIN 3종 | **NL · Hash · Sort Merge** |
| NL | "둘러쌈, 소량+인덱스" |
| Hash | "=계열, 대량" |
| Sort Merge | "정렬+범위, 대량" |

## 10. 📌 시험 합격 핵심 요약

> **시험장 입실 5분 전 점검**

✅ **옵티마이저 2종**:
   - **RBO**: 규칙 기반 (구식)
   - **CBO**: **비용 기반** (통계, 현재)

✅ **JOIN 처리 3종**:
   - **Nested Loop**: 외부 각 행 × 내부, 소량+인덱스
   - **Hash Join**: 작은 쪽 hash → 큰 쪽 probe, **등치만+대량**
   - **Sort Merge**: 양쪽 정렬 후 병합, 정렬된 대량+범위

✅ **JOIN 방식 비교**:
   | | NL | Hash | Sort Merge |
   |---|---|---|---|
   | 등치 | ✓ | ✓ | ✓ |
   | 비등치 | ✓ | **✗** | ✓ |
   | 인덱스 | 후행 필요 | 불필요 | 불필요 |
   | 대량 | ✗ | ✓ | ✓ |

✅ **실행계획 읽기**: 들여쓰기 깊은 것부터, 같으면 위→아래

✅ **주요 힌트**:
   - `FULL` · `INDEX` · `USE_NL` · `USE_HASH` · `LEADING` · `PARALLEL`

✅ **통계 갱신**: `DBMS_STATS.GATHER_TABLE_STATS`

✅ **빈출**: \"NL = 소량 + 후행 인덱스, Hash = 대량 + 등치\"
