## 1. 엔터티란 무엇인가

**엔터티(Entity)**는 업무 활동에서 사용되거나 관리되는 정보로서, **유일하게 구별되며 영속적으로 존재**하는 사물·사람·장소·사건·개념을 의미한다. 데이터 모델링의 가장 기본 단위이며, RDBMS에서는 일반적으로 **테이블**로 구현된다.

> 💡 **간단히**: 업무에서 \"관리할 가치가 있는 무언가\" = 엔터티

### 엔터티는 \"명사\"

엔터티는 보통 명사로 표현된다. 업무 문장에서 명사를 뽑아 엔터티 후보로 식별한다.

> 예: \"**고객**이 **상품**을 **주문**하면, 우리는 **배송장**을 생성하여 **택배사**에 전달한다.\"
>
> 엔터티 후보: 고객, 상품, 주문, 배송장, 택배사

## 2. 엔터티·인스턴스·속성의 관계

세 개념의 차이를 명확히 구분해야 한다.

| 용어 | 의미 | 예시 |
|---|---|---|
| **엔터티 (Entity)** | 객체의 \"집합\" 또는 \"종류\" | 사원 (테이블) |
| **인스턴스 (Instance)** | 엔터티의 \"개체\" (한 건) | 7369번 사원 \"홍길동\" (행) |
| **속성 (Attribute)** | 인스턴스가 가지는 정보 | 사번, 이름, 입사일 (컬럼) |

```
[사원] ← 엔터티 (테이블)
─────────────────────────
사번   이름    입사일       ← 속성 (컬럼)
─────────────────────────
7369   홍길동  2020-03-01   ← 인스턴스 (행)
7400   김철수  2021-05-15   ← 인스턴스
7500   이영희  2022-01-10   ← 인스턴스
```

## 3. 엔터티의 6대 특징 ⭐⭐⭐

| # | 특징 | 설명 |
|---|---|---|
| 1 | **업무에서 필요한 정보** | 업무 분석으로 도출 — 관리가 필요해야 엔터티 |
| 2 | **유일한 식별자** | PK로 인스턴스를 구분 가능 |
| 3 | **영속적 존재** | 일시적이 아닌 지속 보존 |
| 4 | **2개 이상의 인스턴스의 집합** | 단 하나면 상수에 가까움 |
| 5 | **업무 프로세스에 의해 이용** | 어떤 프로세스도 안 쓰면 불필요 |
| 6 | **반드시 속성을 가짐** | 속성 없는 엔터티는 존재 X |

> 🔑 **암기법: \"업유영2업속\"**  
> **업**무 정보 → **유**일 식별자 → **영**속적 → **2**개 이상 → **업**무 프로세스 → **속**성

### 각 특징 깊이 보기

#### ① 업무에서 필요한 정보
\"우리 회사 이름\" 처럼 단일 상수는 엔터티가 아니다. 업무에서 **여러 건이 발생**하고 관리되어야 엔터티가 된다.

#### ② 유일한 식별자
모든 인스턴스를 구분할 수 있는 식별자가 있어야 한다. 식별자가 없으면 인스턴스를 식별할 수 없어 데이터 무결성이 깨진다.

#### ③ 영속적 존재
순간적으로 발생하고 사라지는 정보(예: 화면 임시 상태)는 엔터티가 아니다.

#### ④ 2개 이상의 인스턴스
오직 \"본사 1개\"만 존재한다면 엔터티가 아니라 상수에 가깝다. **여러 건의 인스턴스가 발생**해야 엔터티.

#### ⑤ 업무 프로세스가 이용
어떤 업무 프로세스도 사용하지 않는다면 그 정보는 관리할 가치가 없다.

#### ⑥ 반드시 속성을 가짐
속성이 없으면 데이터를 표현할 수 없다. **최소 1개 이상의 속성** 필수.

## 4. 엔터티의 분류

### 4-1. 유무형에 따른 분류

| 분류 | 설명 | 예시 |
|---|---|---|
| **유형 엔터티 (Tangible)** | 물리적 형태가 있음 | 사원, 상품, 자동차, 건물 |
| **개념 엔터티 (Conceptual)** | 추상적·개념적 정보 | 부서, 학과, 계정과목 |
| **사건 엔터티 (Event)** | 행위·이벤트의 발생 | 주문, 결재, 강의수강, 입사 |

### 4-2. 발생 시점에 따른 분류 ⭐⭐⭐ (시험 빈출)

| 분류 | 설명 | 예시 | 의존 |
|---|---|---|---|
| **기본/키엔터티** | 독립적 발생, 다른 엔터티의 부모 | 사원, 부서, 고객, 상품 | 없음 (독립) |
| **중심엔터티** | 기본엔터티로부터 발생, 업무 중심 | 주문, 계약, 매출, 청구 | 기본엔터티 |
| **행위엔터티** | 두 개 이상 엔터티 간 행위로 발생 | 주문상세, 결재내역, 강의수강 | 중심 + 다른 엔터티 |

> 🔑 **암기법: \"기중행\"** (기본 → 중심 → 행위)

```
[고객] (기본) ──── [주문] (중심) ──── [주문상세] (행위) ──── [상품] (기본)
```

## 5. 강한 엔터티 vs 약한 엔터티

| 종류 | 설명 |
|---|---|
| **강한 엔터티 (Strong)** | 자기 자신의 PK만으로 인스턴스 식별 가능 |
| **약한 엔터티 (Weak)** | 다른 엔터티의 PK에 의존해야 식별 가능 |

```
[주문] (강한)
└── [주문상세] (약한)  ← 주문번호 + 상품번호 (복합 PK)
```

**약한 엔터티**는 부모 엔터티가 사라지면 의미를 잃는다. 보통 **식별 관계**로 연결된다.

## 6. 엔터티 명명 규칙

좋은 엔터티 이름은 **명확하고 일관성** 있어야 한다.

| # | 규칙 | 설명 |
|---|---|---|
| 1 | **현업 용어 사용** | 개발자 임의어 X, 업무 담당자가 이해 가능한 이름 |
| 2 | **단수 명사** | 고객 ○, 고객들 ✗ |
| 3 | **약어 지양** | CUS ✗, 고객 ○ |
| 4 | **유일성** | 같은 이름의 엔터티 둘 ✗ |
| 5 | **고유 의미** | 모호한 단어 회피 (\"정보\", \"데이터\" 같은 일반어) |

## 7. ERD 표기법

### IE (Information Engineering) 표기법

가장 널리 사용되는 표기법.

```
┌─────────────┐
│   엔터티명    │  ← 둥근 사각형 또는 사각형
├─────────────┤
│ # PK 속성    │  ← # 또는 굵게 = 식별자
│   일반 속성   │
│ * NOT NULL  │  ← * = 필수
│ ○ NULL OK   │  ← ○ = 선택
└─────────────┘
```

### Barker 표기법

영국 출신의 표기법. Oracle 도구가 자주 사용.

```
┌─────────────┐
│   엔터티명    │
│ # PK         │
│ * 필수 속성   │
│ ○ 선택 속성   │
└─────────────┘
```

### 관계 표기 (IE)

```
[고객] ──┤<──── [주문]
       1    M
```

| 기호 | 의미 |
|---|---|
| `┤` 또는 `|` | 1 (정확히 하나) |
| `<` (까마귀발) | M (여러 개) |
| `○` | 0 (선택) |
| `┼` | 1 이상 |
| 실선 | 식별 관계 |
| 점선 | 비식별 관계 |

## 8. 엔터티 도출 시 고려사항

1. **업무 분석 결과**에서 명사 추출
2. 인스턴스가 **2개 이상 발생**할 가능성 확인
3. **유일한 식별자** 도출 가능 여부
4. 다른 엔터티와의 **관계**가 명확한지
5. 업무 **프로세스에서 어떻게 사용**되는지

### 통합 vs 분리 기준

비슷한 엔터티를 통합할지 분리할지 결정 기준:

- **유사 속성이 80% 이상**: 통합 + 구분 컬럼 (예: 정규직/계약직 → 직원)
- **속성이 다르고 라이프사이클이 다름**: 분리
- **업무 프로세스가 명확히 다름**: 분리

## 9. ⚠️ 자주 틀리는 함정

1. **\"엔터티는 반드시 모든 속성에 값이 있어야 한다\"** → ✗ NULL 허용 속성 가능 (PK 제외)
2. **\"엔터티는 1개의 인스턴스만 가질 수 있다\"** → ✗ 2개 이상 필요
3. **\"속성이 없어도 엔터티가 될 수 있다\"** → ✗ 반드시 속성 보유
4. **\"개념 엔터티는 추상적이라 엔터티가 아니다\"** → ✗ 추상적이어도 엔터티
5. **\"행위 엔터티는 기본 엔터티의 일종\"** → ✗ 별개 분류
6. **\"엔터티명은 동사도 가능\"** → ✗ 명사 사용
7. **\"엔터티는 ERD에서 마름모로 표기\"** → ✗ 사각형 (마름모는 관계)
8. **\"단 1건이 있어도 엔터티\"** → ✗ 2개 이상 필요

## 10. 📝 기출 출제 패턴

### 패턴 A: 엔터티 특징 ⭐ 최빈출
> \"다음 중 엔터티의 특징으로 옳지 않은 것은?\"
- 6대 특징 중 하나가 변형되어 출제
- 주요 함정: \"모든 속성에 값\", \"1개의 인스턴스\", \"속성 없음\"

### 패턴 B: 분류 구분
> \"발생 시점에 따른 분류로 옳지 않은 것은?\"
- 기본/중심/행위에 \"물리/논리\" 같은 가짜 답 섞임

### 패턴 C: 명명 규칙
> \"엔터티 명명 규칙으로 적절하지 않은 것은?\"
- 복수형, 약어, 개발자 임의 작명 등이 오답

### 패턴 D: 엔터티 vs 인스턴스
> \"다음 중 엔터티가 아닌 것은?\"
- 단일 상수, 일시 정보 등이 오답 후보

## 11. 🔑 암기법 종합

| 항목 | 암기법 |
|---|---|
| **6대 특징** | **업유영2업속** (업무·유일·영속·2+·업무프로세스·속성) |
| **발생 분류** | **기중행** (기본→중심→행위) |

| **ERD 기호** | \"엔터티=사각형, 관계=선/마름모, 속성=원\" |

## 12. 📌 시험 합격 핵심 요약

> **시험장 입실 5분 전 점검**

✅ **엔터티 = 업무에서 관리할 의미 있는 정보의 집합**

✅ **6대 특징 = 업유영2업속**:
   1. **업**무 정보  
   2. **유**일 식별자  
   3. **영**속적 존재  
   4. **2**개 이상 인스턴스  
   5. **업**무 프로세스 이용  
   6. **속**성 필수

✅ **3대 분류 (발생) = 기중행**:
   - 기본/키 (독립): 사원, 고객
   - 중심 (기본에서 발생): 주문, 계약
   - 행위 (2+ 엔터티 관계): 주문상세

✅ **3대 분류 (유무형) = 유개사**:
   - 유형, 개념, 사건

✅ **명명**: 현업 용어, 단수, 약어 X, 유일

✅ **인스턴스 vs 속성**:
   - 엔터티 = 테이블
   - 인스턴스 = 행 (1건)
   - 속성 = 컬럼

✅ **함정 1순위**: \"모든 속성에 값 필수\" → 거짓 (NULL 허용 속성)

✅ **함정 2순위**: \"1개 인스턴스도 엔터티\" → 거짓 (2개 이상)

✅ **ERD 표기**: 사각형(엔터티), 선·까마귀발(관계), 동그라미(선택성)
