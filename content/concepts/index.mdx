## 1. 인덱스란?

테이블의 검색 성능을 높이기 위한 **별도의 정렬된 자료구조**. 책의 \"색인\"과 같은 역할.

> 💡 인덱스 = 검색 ↑ + DML(INSERT/UPDATE/DELETE) 비용 ↑ (트레이드오프)

## 2. 인덱스 종류 ⭐⭐

### 2-1. B-Tree 인덱스 (기본·최다 사용)

```
        [50]
       /    \
   [20]      [80]
   /  \      /  \
 [10] [30] [70] [90]
```

| 특징 | 설명 |
|---|---|
| 균형 트리 | 모든 리프 노드 깊이 동일 |
| 정렬 보존 | 범위 검색 빠름 (BETWEEN, <, >) |
| 등치 검색 | = 도 빠름 |
| **NULL** | **인덱스에 저장 X** (Oracle) |

### 2-2. Bitmap 인덱스

```sql
CREATE BITMAP INDEX idx_gender ON emp (gender);
```

| 특징 | 설명 |
|---|---|
| 카디널리티 낮음 | 값 종류가 적은 컬럼 (성별, 상태) |
| AND/OR/NOT | 비트 연산 매우 빠름 |
| 용도 | DW (Data Warehouse) |
| OLTP | 부적합 (락 광범위) |

### 2-3. 함수 기반 인덱스 (Function-Based)

```sql
CREATE INDEX idx_upper_name ON emp (UPPER(name));

SELECT * FROM emp WHERE UPPER(name) = 'KIM';  -- ✓ 인덱스 활용
```

### 2-4. 결합 인덱스 (Composite)

```sql
CREATE INDEX idx_dept_sal ON emp (deptno, sal);
```

> ⚠️ **컬럼 순서가 중요** — 선행 컬럼부터 활용

```sql
WHERE deptno = 10 AND sal > 1000   -- ✓ 인덱스 활용
WHERE sal > 1000                    -- ✗ 활용 어려움
```

> 🔑 **암기법: "비함결B"** (B-Tree·Bitmap·함수·결합)

## 3. 인덱스 무력화 함정 ⭐⭐⭐ (시험 1순위)

> 📌 다음 경우 인덱스가 **사용되지 않거나 효율이 떨어진다**.

### 3-1. 인덱스 컬럼에 연산·함수 적용

```sql
WHERE SUBSTR(name, 1, 1) = 'K'        -- ✗ 함수
WHERE sal * 12 > 100000                -- ✗ 연산
WHERE name = 'KIM' || ''               -- ✗ 결합
```

### 3-2. 묵시적 형변환

```sql
-- empno가 NUMBER 컬럼
WHERE empno = '7369'    -- 묵시적: '7369' → 7369
```

### 3-3. NULL 비교

```sql
WHERE name IS NULL      -- ✗ B-Tree에 NULL 없음
```

### 3-4. 부정 비교

```sql
WHERE deptno <> 10               -- ✗
WHERE deptno NOT IN (10, 20)     -- ✗ (대부분)
```

### 3-5. LIKE 선두 와일드카드

```sql
WHERE name LIKE '%KIM%'    -- ✗
WHERE name LIKE 'KIM%'     -- ✓
```

> 🔑 **암기법: "함변NULL부LIKE"** (함수·변환·NULL·부정·LIKE 선두)

## 4. 인덱스를 추가하면 안 되는 경우

- **자주 갱신**되는 컬럼
- 카디널리티가 너무 **낮은** 컬럼 (B-Tree 부적합)
- 데이터가 너무 **적은** 테이블
- 검색에 거의 사용되지 않는 컬럼

## 5. PK·UNIQUE와 인덱스

| 제약 | 인덱스 |
|---|---|
| PRIMARY KEY | 자동 **UNIQUE INDEX** |
| UNIQUE | 자동 **UNIQUE INDEX** |

## 6. 통계 정보와 옵티마이저

```sql
EXEC DBMS_STATS.GATHER_TABLE_STATS('SCOTT', 'EMP');
```

통계가 오래되면 잘못된 계획 선택 → 주기적 갱신.

## 7. ⚠️ 자주 틀리는 함정

1. **\"인덱스는 무조건 좋다\"** → ✗ DML 비용 ↑
2. **\"NULL도 B-Tree에 저장\"** → ✗ Oracle 기본 X
3. **\"결합 인덱스 컬럼 순서 무관\"** → ✗ 선행 중요
4. **\"함수 사용해도 인덱스 활용\"** → ✗ 무력화 (함수 기반 제외)
5. **\"`LIKE '%KIM%'`도 활용\"** → ✗
6. **\"PK는 인덱스가 아니다\"** → ✗ 자동 UNIQUE INDEX

## 9. 🔑 암기법 종합

| 항목 | 암기법 |
|---|---|
| 4종 | **비함결B** |
| 무력화 | **함변NULL부LIKE** |
| 결합 | "선행 컬럼 필수" |
| PK | "자동 UNIQUE INDEX" |

## 10. 📌 시험 합격 핵심 요약

> **시험장 입실 5분 전 점검**

✅ **4종 = 비함결B**:
   - B-Tree (기본)
   - Bitmap (카디널리티 ↓, DW)
   - 함수 기반
   - 결합 (선행 컬럼 중요)

✅ **무력화 = 함변NULL부LIKE**:
   - **함**수 적용
   - 묵시적 **변**환
   - **NULL** 비교
   - **부**정 비교
   - **LIKE** 선두 와일드카드

✅ **자동 인덱스**: PK · UNIQUE → UNIQUE INDEX

✅ **NULL은 B-Tree에 없음**

✅ **DML 비용 ↑** 트레이드오프

✅ **빈출**: \"인덱스 컬럼에 함수 → 무력화\"
