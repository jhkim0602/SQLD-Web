## 1. 관계란?

**관계(Relationship)**는 두 엔터티의 인스턴스 사이에서 발생하는 **연관성**이다. 데이터 모델링에서 \"누가 누구와 어떻게 연결되는가\"를 표현한다.

> 💡 데이터 모델링 = **엔터티 도출 → 속성 정의 → 관계 설정**의 반복

```
[고객] ────주문하다──── [주문]
       1       M

해석: 한 고객은 여러 주문을 가질 수 있고,
      한 주문은 한 고객에게 속한다.
```

## 2. 관계 표기의 3대 요소 ⭐⭐⭐

| # | 요소 | 영문 | 설명 |
|---|---|---|---|
| 1 | **관계명** | Relationship Name | 관계의 이름 (동사) |
| 2 | **관계 차수** | Cardinality | 1:1, 1:M, M:N |
| 3 | **관계 선택성** | Optionality | 필수(Mandatory) / 선택(Optional) |

> 🔑 **암기법: \"관차선\"** (관계명·차수·선택성)

### ① 관계명 (Relationship Name)

관계의 이름. 두 엔터티 사이에서 어떤 행위·연관이 이뤄지는지를 명사 또는 동사로 표현.

- 명사형: 소속, 주문, 계약
- 동사형: 주문하다, 소속되다, 계약하다

> 💡 양방향 관점 모두에서 의미가 되는 이름이 좋음.
> 예: 고객 ↔ 주문 = \"주문하다 / 주문되다\"

### ② 관계 차수 (Cardinality)

한 엔터티의 인스턴스가 다른 엔터티의 인스턴스와 **몇 개**의 관계를 맺는가.

| 차수 | 의미 | 예시 |
|---|---|---|
| **1 : 1** | 일대일 | 사원 ↔ 사원증, 사람 ↔ 주민번호 |
| **1 : M** | 일대다 (가장 흔함) | 고객 ↔ 주문, 부서 ↔ 사원 |
| **M : N** | 다대다 | 학생 ↔ 과목, 작가 ↔ 책 |

### ③ 관계 선택성 (Optionality)

관계 참여가 **필수**인가 **선택**인가.

| 선택성 | 설명 | FK 처리 |
|---|---|---|
| **필수 (Mandatory)** | 반드시 관계 참여 | FK **NOT NULL** |
| **선택 (Optional)** | 참여 안 할 수 있음 | FK **NULL 허용** |

```
사원 ────속한다──── 부서
       선택        필수

해석:
- 사원은 부서 미배정 가능 (FK NULL OK)
- 부서는 반드시 존재 (PK NOT NULL)
```

## 3. M:N 관계의 해소 ⭐⭐ (시험 빈출)

**M:N은 RDBMS에서 직접 구현 불가** → **교차 엔터티(Associative Entity)**로 분해.

```
[학생] ──M:N── [과목]
         ↓ 분해
[학생] ──1:M── [수강] ──M:1── [과목]
              ↑
        교차 엔터티 (학번, 과목번호, 학기, 성적)
```

### 왜 분해해야 하나?

RDBMS의 외래키는 단일 값을 가진다. 한 행이 여러 부모를 참조할 수 없다.

```sql
-- ✗ 한 행에 여러 과목 참조 불가
CREATE TABLE 수강 (
  학번 NUMBER,
  과목번호1 NUMBER,   -- 이상한 구조
  과목번호2 NUMBER,
  과목번호3 NUMBER
);

-- ✓ 교차 엔터티 (1:M + M:1)
CREATE TABLE 수강 (
  학번 NUMBER,
  과목번호 NUMBER,
  학기 VARCHAR2(10),
  성적 CHAR(2),
  PRIMARY KEY (학번, 과목번호, 학기)
);
```

### 교차 엔터티는 어떤 엔터티?

대부분 **행위 엔터티**가 된다. 추가 속성(학기·성적·일자 등)을 가질 수 있어 단순한 매핑 이상의 의미를 보유.

## 4. 식별 관계 vs 비식별 관계 ⭐⭐

부모의 PK가 자식에서 **어떤 역할**을 하는가에 따른 분류.

| 종류 | 부모 PK 처리 | 자식 종속성 | ERD 표기 | FK NULL |
|---|---|---|---|---|
| **식별 관계 (Identifying)** | **자식의 PK + FK** | 강함 | **실선** | 불가 (PK이므로) |
| **비식별 관계 (Non-Identifying)** | **자식의 일반 속성 (FK만)** | 약함 | **점선** | 허용 가능 |

### 식별 관계 예

```
[주문] ──식별 관계── [주문상세]
- 주문번호 (PK)         - 주문번호 (PK + FK)  ← 부모의 PK가 자식의 PK 일부
                       - 상품번호 (PK)
                       - 수량
```

\"주문상세\"는 \"주문\" 없이 존재할 수 없다 → **강한 종속**.

### 비식별 관계 예

```
[부서] ──비식별 관계── [사원]
- 부서ID (PK)           - 사번 (PK)
                       - 이름
                       - 부서ID (일반 속성, FK)  ← 일반 컬럼
```

사원은 부서 없이도 존재 가능 (deptno = NULL) → **약한 종속**.

### 선택 기준

| 상황 | 권장 |
|---|---|
| 자식이 부모 없이 존재 불가 | 식별 관계 |
| 자식이 독립적으로 의미 보유 | 비식별 관계 |
| 자식 PK가 너무 길어짐 | 비식별 관계 (또는 인조키) |
| 부모 PK가 자주 변경 | 비식별 관계 |

## 5. 자기 참조 관계 (Recursive)

한 엔터티가 자기 자신과 관계를 맺는 경우.

```
[사원] ──매니저── [사원]
- 사번 (PK)
- 이름
- mgr (FK → empno)  ← 자기 자신 참조
```

```sql
CREATE TABLE emp (
  empno NUMBER PRIMARY KEY,
  ename VARCHAR2(50),
  mgr NUMBER,
  FOREIGN KEY (mgr) REFERENCES emp(empno)
);
```

활용:
- 조직도 (사원 - 매니저)
- 카테고리 (대분류 - 중분류 - 소분류)
- 게시판 답글

조회: **SELF JOIN** 또는 **CONNECT BY** (계층형 질의).

## 6. 관계의 표기법 (ERD) ⭐

### IE (Information Engineering) 표기법

```
[고객] ──○──────<── [주문]
       (선택)  (M, 까마귀발)
       1       M

[학생] ──┤──────────┼── [학생증]
       1            1
       (필수)        (필수)
```

| 기호 | 의미 |
|---|---|
| `┤` 또는 `|` | 1 (정확히 하나) |
| `<` (까마귀발) | M (여러 개) |
| `○` | 0 (선택, NULL 가능) |
| `┼` | 1 이상 |

### Barker 표기법

```
[엔터티1] ──── [엔터티2]
         실선  점선     ← 라인 스타일로 필수/선택 표현
```

- 실선: 필수
- 점선: 선택
- 까마귀발은 동일

## 7. 관계의 페어링 (Pairing)

관계는 인스턴스 간 페어링으로 표현된다.

```
고객 인스턴스         주문 인스턴스
  김철수    ────────  주문 #1
  김철수    ────────  주문 #2
  이영희    ────────  주문 #3
  박지성    (페어링 없음 - 주문 없는 고객)
```

LEFT OUTER JOIN으로 페어링 + 미페어링 모두 표현 가능.

## 8. 관계 도출 절차

1. **두 엔터티 간 연결 가능성** 확인
2. **관계명** 부여 (동사 또는 명사)
3. **차수** 결정 (1:1, 1:M, M:N)
4. **선택성** 결정 (필수 / 선택)
5. **식별성** 결정 (식별 / 비식별)
6. **M:N이면 교차 엔터티로 분해**
7. **FK 컬럼** 추가

## 9. ⚠️ 자주 틀리는 함정

1. **\"M:N 관계는 그대로 구현해도 된다\"** → ✗ 교차 엔터티 필수
2. **\"외래키는 NULL을 가질 수 없다\"** → ✗ **선택 관계라면 허용**
3. **\"관계 차수와 선택성은 같은 것\"** → ✗ 다른 개념
4. **\"비식별 관계의 FK는 항상 NOT NULL\"** → ✗ 선택성에 따라 다름
5. **\"식별 관계는 항상 비식별 관계보다 좋다\"** → ✗ 상황 따라 다름
6. **\"1:1 관계는 한쪽만 다른 쪽 정보를 안다\"** → ✗ 양방향 조회 가능
7. **\"관계는 마름모로 표기\"** → △ Chen 표기법은 마름모, IE는 선
8. **\"자기 참조 관계는 1:1만 가능\"** → ✗ 1:M (사원-부하)도 가능

## 10. 📝 기출 출제 패턴

### 패턴 A: 표기 요소 ⭐ 빈출
> \"관계의 표기 요소가 아닌 것은?\"
- 관계명/차수/선택성에 \"관계가중치\" 같은 가짜 답

### 패턴 B: 차수 vs 선택성
> \"관계 차수에 대한 설명으로 옳은 것은?\"
- 차수와 선택성을 헷갈리게

### 패턴 C: M:N 해소
> \"M:N 관계의 적절한 해소 방법은?\"
- 교차 엔터티 분해가 정답

### 패턴 D: 식별/비식별 구분
> \"식별 관계의 특징으로 옳지 않은 것은?\"
- 자식의 PK 포함 여부, ERD 표기 (실선/점선)

### 패턴 E: FK NULL 허용
> \"FK는 NULL을 가질 수 있다 (O/X)\"
- O (선택 관계)

## 11. 📌 ERD·모델링 한눈

> **분류 · ERD 표기 · 명명 규칙**

✅ **관계 3요소 = 관차선** (관계명·차수·선택성)

✅ **차수 (Cardinality)**: 1:1, 1:M, M:N
   - **M:N은 교차 엔터티로 분해**
   - 교차 엔터티는 보통 **행위 엔터티**

✅ **선택성 (Optionality)**:
   - 필수 → NOT NULL FK
   - 선택 → NULL 허용 FK

✅ **식별성**:
   - 식별 관계 → **실선**, 부모PK = 자식 **PK+FK**
   - 비식별 관계 → **점선**, 부모PK = 자식 **일반 속성(FK)**

✅ **FK는 NULL 허용 가능** (선택 관계의 경우)

✅ **PK는 NULL 불허** (개체 무결성)

✅ **자기 참조 관계** = 같은 엔터티 (예: 사원-매니저)

✅ **빈출**: \"FK는 NULL 가능\" → ○

✅ **빈출**: \"M:N 그대로 구현\" → ✗ (교차 엔터티 필수)

✅ **빈출**: \"식별 관계 ERD\" → 실선

### 🔑 암기법 정리

| 항목 | 암기법 |
|---|---|
| 3대 표기 요소 | **관차선** (관계명·차수·선택성) |
| 차수 | 1:1, 1:M, M:N (M:N은 분해) |
| 선택성 | **필수=NOT NULL, 선택=NULL OK** |
| 식별성 | **식별=실선·PK포함, 비식별=점선·일반속성** |
| ERD 기호 | \"까마귀발=M, 동그라미=선택\" |
