## 1. 정의

**관계(Relationship)**는 두 엔터티 간 인스턴스의 페어링(pairing)을 의미한다. 데이터 모델링에서 \"누구와 누가 어떻게 연결되는가\"를 표현.

```
[고객] ────주문하다──── [주문]
        1       M

해석: 한 고객은 여러 주문을 가질 수 있다 (1:M)
```

## 2. 관계의 3가지 표기 요소 ⭐⭐⭐

| # | 요소 | 설명 |
|---|---|---|
| 1 | **관계명 (Relationship Name)** | 관계의 이름 (동사) |
| 2 | **관계 차수 (Cardinality)** | 1:1, 1:M, M:N |
| 3 | **관계 선택성 (Optionality)** | 필수(Mandatory) / 선택(Optional) |

> 🔑 **암기법: "관차선"** (관계명 → 차수 → 선택성)

## 3. 관계 차수 (Cardinality)

한 엔터티의 인스턴스가 다른 엔터티의 인스턴스와 **몇 개**의 관계를 맺는가.

| 차수 | 의미 | 예시 |
|---|---|---|
| **1 : 1** | 일대일 | 사원 — 사원증 |
| **1 : M** | 일대다 (가장 흔함) | 고객 — 주문 |
| **M : N** | 다대다 | 학생 — 과목 |

### M:N 관계의 해소 ⭐ 빈출

M:N은 RDBMS에서 직접 구현 불가 → **교차 엔터티**로 분해.

```
학생 ──M:N── 과목
        ↓ 분해
학생 ──1:M── 수강 ──M:1── 과목
              ↑
        교차 엔터티 (수강신청)
        속성: 학번, 과목번호, 학기, 성적
```

## 4. 관계 선택성 (Optionality)

관계 참여가 **필수**인가 **선택**인가.

| 선택성 | 설명 | FK 처리 |
|---|---|---|
| **필수 (Mandatory)** | 반드시 관계 참여 | FK **NOT NULL** |
| **선택 (Optional)** | 참여하지 않을 수 있음 | FK **NULL 허용** |

```
사원 ────속한다──── 부서
       선택        필수

해석: 사원은 부서 미배정 가능 (FK NULL),
      부서는 반드시 존재 (PK NOT NULL)
```

## 5. 관계의 식별성 (Identifying vs Non-Identifying) ⭐⭐

부모의 PK가 자식에서 어떤 역할을 하는가.

| 종류 | 설명 | 자식에서 부모 PK |
|---|---|---|
| **식별 관계 (Identifying)** | 강한 종속 | **PK + FK** (자식 PK의 일부) |
| **비식별 관계 (Non-Identifying)** | 약한 종속 | **일반 속성 (FK)** |

### ERD 표기

| 관계 | 선 |
|---|---|
| 식별 관계 | **실선** |
| 비식별 관계 | **점선** |

### 선택 기준

- **식별 관계**: 자식이 부모 없이 존재 불가 (예: 주문 → 주문상세)
- **비식별 관계**: 자식이 독립적 (예: 부서 → 사원)

## 6. ERD 표기 (IE 표기법)

```
[고객] ──○──────<── [주문]
       (선택)  (M, 까마귀발)
       1       M

[학생] ──┤──────────┼── [학생증]
       1            1
       (필수)        (필수)
```

### 표기 기호

| 기호 | 의미 |
|---|---|
| `┤` 또는 `|` | 1 (정확히 하나) |
| `<` 또는 `>` (까마귀발) | M (여러 개) |
| `○` | 0 (선택, NULL 가능) |
| `┼` | 1 이상 |

## 7. ⚠️ 자주 틀리는 함정

1. **\"M:N 관계는 그대로 구현해도 된다\"** → ✗ 교차 엔터티로 해소 필수
2. **\"외래키는 NULL을 가질 수 없다\"** → ✗ **선택 관계라면 NULL 허용**
3. **\"관계 차수와 선택성은 같은 것\"** → ✗ 다른 개념
4. **\"비식별 관계의 FK는 항상 NOT NULL\"** → ✗ 선택성에 따라 다름
5. **\"식별 관계는 항상 비식별 관계보다 좋다\"** → ✗ 상황 따라 다름

## 8. 📝 기출 출제 패턴

### 패턴 A: 표기 요소
> \"관계의 표기 요소가 아닌 것은?\"
- 관계명/차수/선택성에 \"관계가중치\", \"관계우선순위\" 같은 가짜 답 추가

### 패턴 B: 차수 의미
> \"관계 차수에 대한 설명으로 옳은 것은?\"
- 차수와 선택성을 헷갈리게 함

### 패턴 C: M:N 해소
> \"M:N 관계의 적절한 해소 방법은?\"
- 교차 엔터티 분해가 정답

### 패턴 D: 식별/비식별 구분
> \"식별 관계의 특징으로 옳지 않은 것은?\"
- 자식의 PK 포함 여부, ERD 표기 (실선/점선)

## 9. 🔑 암기법 종합

| 항목 | 암기법 |
|---|---|
| 3대 표기 요소 | **관차선** (관계명·차수·선택성) |
| 차수 | **1:1, 1:M, M:N** (M:N은 분해) |
| 선택성 | **필수 = NOT NULL, 선택 = NULL OK** |
| 식별성 | **식별=실선·PK포함, 비식별=점선·일반속성** |

## 10. 📌 시험 합격 핵심 요약

> **시험장 입실 5분 전 점검**

✅ **관계 표기 3요소 = 관차선** (관계명·차수·선택성)

✅ **차수 (Cardinality)**: 1:1, 1:M, M:N
   - **M:N은 교차 엔터티로 분해**

✅ **선택성 (Optionality)**: 필수(NOT NULL FK) / 선택(NULL FK)

✅ **식별성**:
   - 식별 관계 → 실선, 부모PK가 자식의 PK+FK
   - 비식별 관계 → 점선, 부모PK가 자식의 일반속성

✅ **FK는 NULL 허용 가능** (선택 관계의 경우)

✅ **PK는 NULL 불허** (개체 무결성)
