## JOIN 한눈에

| 종류 | 의미 | 결과 |
|---|---|---|
| **INNER JOIN** | 양쪽 매칭만 | 매칭 행만 |
| **LEFT OUTER JOIN** | 왼쪽 보존 | 왼쪽 전체 + 매칭 |
| **RIGHT OUTER JOIN** | 오른쪽 보존 | 오른쪽 전체 + 매칭 |
| **FULL OUTER JOIN** | 양쪽 보존 | 양쪽 전체 |
| **CROSS JOIN** | 카티전 곱 | m × n |
| **SELF JOIN** | 자기 참조 | 별칭으로 두 번 |
| **NATURAL JOIN** | 동일 이름 자동 조인 | 공통 컬럼 1번만 |
| **USING (col)** | 명시적 동일 이름 조인 | 공통 컬럼 1번만 |

## 시각화

```
A: {1, 2, 3}      B: {2, 3, 4}

INNER JOIN ON A.x = B.x       LEFT OUTER JOIN
+---+---+                     +---+------+
| A | B |                     | A | B    |
| 2 | 2 |                     | 1 | NULL |
| 3 | 3 |                     | 2 | 2    |
+---+---+                     | 3 | 3    |
                              +---+------+

FULL OUTER JOIN               CROSS JOIN
+------+------+               (3 × 3 = 9 rows)
| A    | B    |
| 1    | NULL |
| 2    | 2    |
| 3    | 3    |
| NULL | 4    |
+------+------+
```

## INNER JOIN

```sql
SELECT e.ename, d.dname
FROM emp e INNER JOIN dept d
  ON e.deptno = d.deptno;

-- INNER 키워드 생략 가능
SELECT e.ename, d.dname
FROM emp e JOIN dept d ON e.deptno = d.deptno;

-- WHERE로 표현 (구식)
SELECT e.ename, d.dname
FROM emp e, dept d
WHERE e.deptno = d.deptno;
```

## OUTER JOIN

### LEFT OUTER JOIN

```sql
-- 부서 없는 사원까지 모두 출력
SELECT e.ename, d.dname
FROM emp e LEFT OUTER JOIN dept d
  ON e.deptno = d.deptno;

-- OUTER 키워드 생략 가능 → LEFT JOIN
```

### Oracle (+) 구문 (구식)

```sql
SELECT e.ename, d.dname
FROM emp e, dept d
WHERE e.deptno = d.deptno(+);   -- ANSI LEFT OUTER 와 동치
```

`(+)`는 **NULL을 채울 반대편**에 붙인다.

| Oracle (+) | ANSI |
|---|---|
| `WHERE A.x = B.y(+)` | `A LEFT OUTER JOIN B ON A.x = B.y` |
| `WHERE A.x(+) = B.y` | `A RIGHT OUTER JOIN B ON A.x = B.y` |
| 양쪽 (+) ← 불가 | `A FULL OUTER JOIN B` |

> ⚠️ 신규 코드는 ANSI 구문 사용. `(+)`는 가독성·기능 모두 제약.

### FULL OUTER JOIN

```sql
SELECT e.ename, d.dname
FROM emp e FULL OUTER JOIN dept d
  ON e.deptno = d.deptno;
```

결과 행 수: `len(A) + len(B) - 매칭_수`

## CROSS JOIN (카티전 곱)

```sql
SELECT * FROM emp CROSS JOIN dept;
-- emp 14건 × dept 4건 = 56건
```

### 의도치 않은 카티전 곱 함정

```sql
-- ON 조건 누락 → 의도치 않은 카티전 곱!
SELECT * FROM emp, dept;   -- 56건 반환

-- 잘못된 조건 → 부분 카티전 곱
SELECT * FROM emp e, dept d, salgrade s
WHERE e.deptno = d.deptno;   -- salgrade와 조인 조건 누락
```

> 📌 **시험 빈출**: `n` 테이블 조인 시 **`n-1`개의 조인 조건**이 필요.

## SELF JOIN

같은 테이블을 두 번 참조. **alias 필수**.

```sql
-- 사원과 매니저 출력
SELECT e.ename AS 사원, m.ename AS 매니저
FROM emp e LEFT OUTER JOIN emp m
  ON e.mgr = m.empno;
```

계층 데이터에 자주 사용. 더 깊은 계층은 `CONNECT BY` 권장.

## USING vs NATURAL JOIN

```sql
-- ON
SELECT * FROM emp e JOIN dept d ON e.deptno = d.deptno;
-- 결과에 e.deptno와 d.deptno 둘 다 등장

-- USING
SELECT * FROM emp JOIN dept USING (deptno);
-- 결과에 deptno 한 번만 등장 (한정자 불가)

-- NATURAL JOIN — 같은 이름 컬럼 자동 조인
SELECT * FROM emp NATURAL JOIN dept;
-- 결과에 deptno 한 번만
```

### NATURAL JOIN 주의

> ⚠️ 양쪽 테이블에 **모든 동명 컬럼**이 자동으로 조인 조건. 의도치 않은 매칭 위험.

```sql
-- 두 테이블에 'updated_at' 같은 공통 컬럼이 있다면
-- 자동으로 그것도 조인 조건에 포함되어 결과가 비어버림
```

→ 실무에서는 거의 사용 안 함. `JOIN ... ON` 권장.

## 옵티마이저의 JOIN 처리 방식

CBO(Cost-Based Optimizer)는 3가지 중 하나 선택:

### 1. Nested Loop (NL Join)

```
for each row in OUTER:
   for each row in INNER:
      if condition: join
```

- **선행 작은 + 후행 인덱스** 조건에서 빠름
- OLTP 환경

### 2. Hash Join

```
phase 1: 작은 테이블로 hash 테이블 생성
phase 2: 큰 테이블 순회하며 hash 조회
```

- **등치 조인 + 대용량**
- 인덱스 불필요
- 메모리 사용 큼

### 3. Sort Merge

```
phase 1: 양쪽 정렬
phase 2: 병합
```

- 이미 정렬된 데이터, 범위 조인
- 등치/비등치 모두 가능

### 비교

| | NL | Hash | Sort Merge |
|---|---|---|---|
| 등치 조인 | ✓ | ✓ | ✓ |
| 비등치 조인 | ✓ | ✗ | ✓ |
| 인덱스 필요 | 후행에 ✓ | ✗ | ✗ |
| 대용량 | ✗ | ✓ | ✓ |
| 소량 | ✓ | ✗ | ✗ |

## 자주 틀리는 함정

> 📌 **시험 빈출 함정 모음**

1. **NULL이 있는 조인 컬럼**
   ```sql
   -- emp.deptno가 NULL인 행은 INNER JOIN 결과에 안 나옴
   -- LEFT OUTER JOIN이면 포함됨 (오른쪽은 NULL)
   ```

2. **LEFT OUTER JOIN의 WHERE 함정**
   ```sql
   -- 의도: 부서 없는 사원도 보기
   SELECT * FROM emp e LEFT JOIN dept d ON e.deptno = d.deptno
   WHERE d.loc = 'SEOUL';
   -- ✗ WHERE가 NULL 행을 걸러내어 사실상 INNER JOIN
   
   -- ✓ ON 조건에 추가
   SELECT * FROM emp e LEFT JOIN dept d
     ON e.deptno = d.deptno AND d.loc = 'SEOUL';
   ```

3. **카티전 곱 결과 수**
   ```sql
   -- emp 14, dept 4 → CROSS JOIN = 56
   -- ON 조건이 모두 일치하지 않으면 INNER = 0
   ```

4. **FULL OUTER 행 수**
   ```sql
   -- A = {1,2,3}, B = {2,3,4}, 매칭 2건
   -- FULL OUTER = 3 + 3 - 2 = 4
   ```

5. **n 테이블 조인 조건 수**: n-1개

## 시험 빈출 포인트

> 📌 **요약**
> - INNER vs OUTER vs CROSS
> - `(+)` 위치 = NULL 채울 쪽
> - LEFT OUTER + WHERE 함정 (ON에 조건 둬야)
> - NATURAL JOIN은 모든 동명 컬럼 자동
> - USING과 NATURAL JOIN은 한정자 불가
> - n개 테이블 → n-1개 조인 조건
> - 옵티마이저 JOIN 방식 3가지 (NL/Hash/Sort Merge)
